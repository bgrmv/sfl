# Бэкап MongoDB: дамп, шифрование, проверка восстановления

Относится к [S6.1](../backlog/E06-data-migration/S6.1.md). Скрипт: [scripts/mongo-backup.mjs](../../scripts/mongo-backup.mjs). Дамп — `mongodump` (архив, gzip), шифрование — [age](https://github.com/FiloSottile/age) на публичный ключ. Строка подключения к проду нигде не хранится: она живёт только в переменной окружения на время команды.

## Быстрая инструкция: сделать бэкап прода вручную

Команды выполняй в терминале dev-container, в корне проекта. Всё займёт около 10 минут. Бэкап нужен до переезда на MVPS и до любых работ с прод-данными; срочным он не является.

**1. Ключ-сейф (один раз).**

```bash
age-keygen -o ~/sfl-backup-key.txt
cat ~/sfl-backup-key.txt
```

- `# public key: age1...` — публичный ключ, не секрет, нужен в шаге 3.
- `AGE-SECRET-KEY-1...` — приватный ключ. Сохрани файл целиком в менеджере паролей: без него бэкап не открыть. Файл в контейнере пропадёт при его пересборке.

**2. Строка подключения к проду.** В Atlas: Database → Connect → Drivers, скопируй `mongodb+srv://user:password@cluster.../`, подставь пароль и имя базы в конце (`.../sfl`).

**3. Бэкап.**

```bash
export SFL_PROD_URI='ВСТАВЬ_СТРОКУ'
export SFL_BACKUP_AGE_RECIPIENT='age1...ПУБЛИЧНЫЙ_КЛЮЧ'
pnpm backup:prod
```

Скрипт только читает прод. В конце он печатает число документов по коллекциям и путь к файлу в `_backups/prod/`. Для строки с паролем можно выключить историю командой `set +o history`.

**4. Копия вне компьютера.** Скопируй оба файла из `_backups/prod/` (`.archive.gz.age` и `.manifest.json`) в облако или на внешний диск. Архив зашифрован.

**5. Проверка.**

```bash
export SFL_BACKUP_AGE_IDENTITY=$HOME/sfl-backup-key.txt
pnpm backup:verify
```

Ожидаемый результат: `OK: all ... collections match the manifest`. Восстановление идёт только в локальную базу `sfl_restore_check`, потом она удаляется.

**6. Уборка.**

```bash
unset SFL_PROD_URI SFL_BACKUP_AGE_RECIPIENT SFL_BACKUP_AGE_IDENTITY
set -o history
```

Файл приватного ключа можно удалить из контейнера, когда он надёжно лежит в менеджере паролей.

**Если что-то пошло не так**

- `set SFL_PROD_URI` — переменные заданы не в том терминале: повтори `export`.
- `ENOTFOUND` или таймаут — проверь строку, пароль и Network Access в Atlas, а также выход контейнера в интернет.
- `counts differ` — база `sfl_restore_check` остаётся для разбора; сохрани вывод таблицы.

## Подробности

### Ключ шифрования

1. Создай пару ключей: `age-keygen -o sfl-backup-key.txt`. Команда печатает публичный ключ `age1...`.
2. **Приватный ключ (файл) сохрани в менеджере паролей и во втором независимом месте.** Потеряешь ключ — бэкапы не расшифровать. Из репозитория и из контейнера его надо убрать после проверки.
3. Публичный ключ не секрет: можно хранить рядом с командами ниже.

Инструменты ставит `bash .devcontainer/install-backup-tools.sh` (его же вызывает `post-create.sh`, в старом контейнере запусти вручную).

## Сделать бэкап прода

```bash
export SFL_PROD_URI='mongodb+srv://<user>:<password>@<cluster>/<db>'   # не коммитить, не писать в .env
export SFL_BACKUP_AGE_RECIPIENT='age1...'                              # публичный ключ
pnpm backup:prod
```

Результат в `_backups/prod/` (папка в `.gitignore`; другое место — `SFL_BACKUP_DIR`):

- `<db>-<дата>.archive.gz.age` — зашифрованный архив;
- `<db>-<дата>.manifest.json` — число документов по коллекциям на момент дампа (без данных).

Скрипт только читает прод: `countDocuments` и `mongodump`. После дампа **скопируй `.age` файл во внешнее хранилище** (вне этой машины и вне репозитория), manifest — рядом.

## Проверить восстановление

```bash
export SFL_BACKUP_AGE_IDENTITY=/путь/к/sfl-backup-key.txt
pnpm backup:verify [файл.age]      # по умолчанию самый свежий
```

Скрипт расшифровывает архив, восстанавливает его в **локальную** базу `sfl_restore_check` (прод не трогает, адреса Atlas и учётные данные в `DATABASE_URL` он отвергает), сравнивает число документов с manifest и при совпадении удаляет временную базу. При расхождении завершается с ошибкой и оставляет базу для разбора.

## Предупреждение при запуске сервера

`pnpm start:dev` перед стартом вызывает `pnpm backup:status`: если в `_backups/prod/` нет бэкапа или он старше 30 дней (`SFL_BACKUP_MAX_AGE_DAYS`), печатается предупреждение. Сервер запускается в любом случае.

## Восстановление после аварии

```bash
age -d -i sfl-backup-key.txt <файл.age> | mongorestore --uri='<куда>' --archive --gzip --drop
```

Для переноса в другое имя базы добавь `--nsFrom='<db>.*' --nsTo='<новая>.*'`.

## Решения

- `age` с публичным ключом, а не пароль: дамп можно делать без интерактивного ввода и без хранения секрета на машине, где запускается команда; расшифровать может только владелец приватного ключа.
- `mongodump`, а не JSON-выгрузка [.devcontainer/db-dump.cjs](../../.devcontainer/db-dump.cjs): архив сохраняет индексы и типы BSON. `db-dump.cjs` остаётся для локальных данных.
