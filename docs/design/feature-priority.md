# Приоритеты функций

Рейтинг всех функций из [feature-review.md](feature-review.md) от самых важных к менее важным. Решение владельца 2026-11-15: основная тема **тёмная**, светлая в конце; **главное — статистика**, остальное второстепенно; **админка первой**, чтобы можно было наполнять контент; матчи 2011–2026 вносят вручную несколько назначенных модераторов; транзакции MongoDB включаем ([ADR 0014](../adr/0014-mongodb-replica-set.md)).

Как читать: чем меньше номер, тем раньше делаем. Уровни A–E совпадают с релизами из [implementation-assessment.md](implementation-assessment.md). Историю для работы выбирают по этому списку: [AGENT.md](../../AGENT.md), «Работа с бэклогом».

## Критерии

1. Влияет ли функция на правильность и наполнение статистики (расчёт, ввод, подтверждение).
2. Блокирует ли она другие функции (роль, статус, домен).
3. Видят ли её все посетители каждый день (рейтинг, игрок, матч).
4. Можно ли отложить без ущерба для статистики (сообщество, личное, украшательства).

## Что откладываем сознательно

- Всё уровня D и E, пока статистика не вносится и не считается правильно.
- Светлая тема и переключатель темы (F100, F67) в самом конце: основная тема тёмная, [S10.50](../backlog/E10-product-features/S10.50.md).
- Порядок голов и история матча необязательны и не влияют на статистику.
- Сравнение, календарь, дни рождения и «Я приду» не нужны для первого релиза.
- Новые провайдеры входа (Apple, Microsoft, Telegram): пока только Google и логин с паролем.
