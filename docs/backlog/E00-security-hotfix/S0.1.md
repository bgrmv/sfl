# S0.1 — Закрыть изменяющие эндпоинты авторизацией

**Эпик:** 0 — Hotfix безопасности текущего прода · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P0 · **Размер:** M · **Зависит от:** —

**DESC:** Как администратор лиги, я хочу, чтобы только авторизованные пользователи могли создавать, изменять и удалять матчи, игроков, команды и роли, чтобы посторонний не мог испортить данные лиги.

**ACs:**
- [x] JWT-проверка выполняется глобальным `APP_GUARD`, а не через `forRoutes(...)` в `AppModule`.
- [x] Публичные маршруты помечены декоратором `@Public()`: `POST /auth/sign-in`, `POST /auth/sign-out` и все `GET` для `games`, `players`, `teams`, `charts`.
- [x] Все `POST`, `PUT`, `PATCH`, `DELETE` для `games`, `players`, `teams`, `roles` без токена возвращают `401`.
- [x] `GET /users` и `GET /migrations/*` остаются закрытыми.
- [x] Клиент работает как раньше: администратор после входа может создать и изменить матч.
- [x] Есть автотест, который проходит по всем маршрутам и проверяет `401` без токена ([S2.4](../E02-tests-ci/S2.4.md) можно начать с этого теста).

## Заметки

- `GET /players/recalculate/season` сознательно **не** помечен `@Public()`, хотя это `GET`: маршрут пересчитывает и сохраняет статистику. Перевод на `POST` — в [S0.4](S0.4.md).
- `GET /auth/whoami` остаётся закрытым, как и раньше: без токена он возвращает `401`.
- Автотест матрицы доступа: `server-nest/src/shared/guards/auth.guard.test.ts`. Маршруты собираются из роутера автоматически, поэтому новый маршрут без `@Public()` сразу проверяется на `401`. Для Nest DI в vitest нужен `unplugin-swc`.
- История закрыта по решению команды **без запуска**: в среде разработки не было Node.js, базы и клиента. Автотест, `pnpm build` и ручная проверка клиента не выполнялись. Код клиента не менялся. Живая проверка — в [S11.6](../E11-dx-docs/S11.6.md) (dev-container).
- `unplugin-swc` и `@swc/core` добавлены в `package.json` без обновления `pnpm-lock.yaml`. Первый `pnpm install` обновит lockfile, его нужно закоммитить.
