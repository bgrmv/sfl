# S0.4 — Пересчёт статистики через POST и с ожиданием результата

**Эпик:** 0 — Hotfix безопасности текущего прода · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P0 · **Размер:** S · **Зависит от:** [S0.1](../E00-security-hotfix/S0.1.md)

**DESC:** Как администратор лиги, я хочу запускать пересчёт статистики сезона защищённым запросом и получать результат после его завершения, чтобы пересчёт нельзя было вызвать случайной ссылкой и я знал, что он прошёл.

**ACs:**
- [x] `GET /players/recalculate/season` заменён на `POST /players/recalculate/season` с телом `{ seasonId, playerIds }`.
- [x] Маршрут требует авторизации.
- [x] `playerIds.forEach(async ...)` заменён на последовательный `for ... of` или `Promise.all`. Ответ отправляется после завершения всех пересчётов.
- [x] Ошибка пересчёта одного игрока попадает в ответ и в лог, а не теряется.
- [x] Клиент обновлён под новый метод, если он вызывает этот маршрут.

## Заметки

- **Сделано 2026-11-12.** `POST /players/recalculate/season` с телом `{ seasonId, playerIds }` (валидация `RecalculateSeasonDTO`, 400 при ошибке); авторизация проверяется глобальным guard, маршрут добавлен в матрицу `auth.guard.test.ts`. В `recalculatePlayersSeasonAndCareerMetadata` вместо `forEach(async)` последовательный `for ... of`; ошибки игроков логируются и возвращаются в `500` в поле `failed`, остальные игроки досчитываются. Побочный эффект: то же поведение теперь у сохранения и удаления матча, где раньше сбой пересчёта терялся, а теперь вернёт `500`. Клиент этот маршрут не вызывает, правок не требуется.
