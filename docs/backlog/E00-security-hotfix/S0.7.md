# S0.7 — Ротация учётных данных после публикации в git

**Эпик:** 0 — Hotfix безопасности текущего прода · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P0 · **Размер:** S · **Зависит от:** —

**DESC:** Как владелец, я хочу заменить учётные данные, которые лежали в публичном репозитории, чтобы по ним нельзя было войти в прод или в базу, даже если кто-то успел их скопировать.

**Контекст.** Репозиторий `bgrmv/sfl` публичный (подтверждено 2026-11-12). В истории git есть `_backups/test.users.json` (220 записей), `server/.env` и `ssl/localhost.key` (см. [S0.5](S0.5.md)). Пароли пользователей в выгрузке фейковые, кроме одного: тестовый администратор `admin@admin.lv`, под которым владелец проверял приложение в проде. Хеш пароля — SHA-512 без соли, подбирается быстро.

**ACs:**
- [ ] Сменён пароль `admin@admin.lv` в проде (или аккаунт удалён/отключён). Новый пароль нигде не повторяет старый и не лежит в репозитории.
- [ ] Проверено, что аккаунт не используется ни на каких других сервисах с тем же паролем.
- [ ] Выяснено, что было в `server/.env` из истории. Если там был пароль или строка подключения MongoDB Atlas, пароль пользователя БД сменён, а при необходимости ограничен список IP.
- [ ] Если в `server/.env` были другие секреты (JWT-ключ, SSL-passphrase и т.п.), они перевыпущены. После смены JWT-ключа старые токены перестают действовать, это нормально.
- [ ] `ssl/localhost.key` и `localhost.crt` из истории не используются нигде кроме localhost. Локальный сертификат перевыпущен.
- [ ] Принято и записано в `## Заметки` решение: чистить историю git (`git filter-repo` по `_backups/`, `server/.env`, `ssl/` + force-push) или нет. Если нет, причина записана (данные фейковые, секреты ротированы). Если да, команда предупреждена о перевыпуске клонов.

## Заметки

- Прод-базу и прод-окружение агент не трогает ([AGENT.md](../../../AGENT.md)): AC выполняет владелец вручную. Если Azure-проект закрывается раньше ([решение 8](../README.md)), первые два AC можно закрыть удалением аккаунта вместе с базой, но пароль Atlas всё равно надо сменить, пока кластер жив.
