# S4.1 — Spike: целевая архитектура Netlify + Supabase

**Эпик:** 4 — Spike и проектирование переезда · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** —

**DESC:** Как разработчик, я хочу сравнить варианты переезда и выбрать один, чтобы не делать работу, которую придётся выбросить.

**ACs:**
- [ ] Сравнены варианты:
  - **A** — Angular на Netlify → Supabase напрямую (supabase-js, RLS). Расчёт статистики в Postgres-функциях или Edge Functions. NestJS отключается.
  - **B** — NestJS как Netlify Functions + Supabase Postgres через ORM.
  - **C** — только Netlify для клиента, база остаётся в MongoDB (Atlas).
- [ ] Для каждого: объём работ, стоимость в месяц, холодный старт, сложность локальной разработки, риски.
- [ ] Прототип варианта A: одна таблица, одна RLS-политика, чтение из Angular, одна функция расчёта.
- [ ] Решение записано в ADR. Помеченные истории эпиков 1–3 подтверждены или закрыты.
