# S4.1 — Spike: монолит Nest + Angular SSR на VPS

**Эпик:** 4 — Spike и проектирование переезда · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** —

**DESC:** Как разработчик, я хочу проверить целевую архитектуру на прототипе и закрыть оставшиеся решения, чтобы не делать работу, которую придётся выбросить.

**Уже решено** (2026-10-25):
- **Архитектура:** один процесс Nest. Он отдаёт `/rest/*` и рендерит Angular (с Material) через `AngularNodeAppEngine` на остальных маршрутах. Там же живут cron и websockets.
- **Хостинг:** VPS, Docker Compose (`edge-caddy → app → [mongodb]`). VPS общий для нескольких проектов: SFL живёт в `/opt/sfl/`, общий прокси — в `/opt/edge/` ([S7.9](../E07-vps-hosting/S7.9.md)).
- **Переход с Azure на MVPS** — сразу на целевую архитектуру. До переключения ([S6.7](../E06-data-migration/S6.7.md)) Azure получает только hotfix'ы эпика 0.
- **База:** MongoDB остаётся. На первом этапе прод на MVPS работает с текущим MongoDB Atlas. После отключения Azure дамп переносится в compose на MVPS ([S6.9](../E06-data-migration/S6.9.md)). Postgres не планируется.
- **Сервер куплен** (2026-10-25): MVPS, тариф SSD BASIC, Ubuntu 26.04, €8.47 в месяц. Характеристики (vCPU, RAM, диск, локация) нужно дописать сюда после установки.
- **Деплой:** GitHub Actions → образ в GHCR → ssh `docker compose pull && up -d`. Вся инфраструктура описана файлами в репозитории.

**Отклонённые варианты:**
- **Angular на Netlify → Supabase напрямую (RLS, Edge Functions), без своего бэкенда.** Netlify не держит постоянные процессы, а cron и websockets нужны. Сервер команде понятнее, чем RLS и SQL-функции.
- **NestJS в Netlify Functions.** Холодный старт, лимит времени на пересчёт статистики, нет websockets.
- **PaaS (Render, Railway, Fly.io).** Рабочий вариант. Отклонён в пользу VPS по цене за always-on инстанс и ради полного контроля.
- **Coolify на VPS.** Ещё один слой со своей памятью и обновлениями. Compose + Caddy проще.
