# S3.26 — Steiger как проверка структуры FSD

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P3 · **Размер:** S · **Зависит от:** [S3.8](S3.8.md)

**DESC:** Как разработчик, я хочу, чтобы официальный линтер FSD Steiger проверял структуру слайсов (лишние и одиночные слайсы, имена файлов по роли), потому что правила импортов из [S3.8](S3.8.md) этого не видят.

**ACs:**

- [ ] В истории выбрана версия Steiger и плагин (`@feature-sliced/steiger-plugin`); пробный прогон по `client/src` показал, что он читает алиасы `@entities/*`, `@features/*`, `@pages/*`, `@shared/*`.
- [ ] Правила импортов Steiger не дублируют ESLint из S3.8 (отключены или совпадают), конфиг `steiger.config.ts` с причинами отключённых правил.
- [ ] Шаг `client:fsd` добавлен в `pnpm check`; найденные нарушения исправлены или занесены в исключения с причиной (мёртвые слайсы `captain-to-add`, `captains-selection`, `games-table` решаются вместе с [S10.8](../E10-product-features/S10.8.md)).
- [ ] `AGENT.md` и [ADR 0016](../../adr/0016-client-fsd-layers-and-cross-imports.md) упоминают проверку.

## Заметки

- Решение владельца 2026-11-16 (вопрос «Steiger или свой линтер»): пользовательские правила ESLint из S3.8 остаются, Steiger добавляется как дополнение для структуры.
