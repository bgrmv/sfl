# S3.7 — Привести состояние клиента к одному подходу

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S1.4](../E01-dependency-upgrades/S1.4.md)

**DESC:** Как разработчик, я хочу один способ управления состоянием на клиенте, чтобы не разбираться в двух библиотеках.

**ACs:**
- [ ] Решено: используем `@ngrx/signals`. `provideStore()` из `@ngrx/store` без редьюсеров удалён, если нигде не используется (сейчас импортируется только в `app.config.ts`).
- [ ] `@ngrx/component-store` (стор капитанов, `entities/captains/store/captains-store.ts` и `captains-page`) заменён на `signalStore`, пакет удалён из зависимостей.
- [ ] Devtools подключены способом, который подходит для signal store, или убраны.
- [x] Решение записано в ADR ([S3.9](../E03-architecture/S3.9.md)).
