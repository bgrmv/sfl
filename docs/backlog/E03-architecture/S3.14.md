# S3.14 — Пересчёт метаданных всех матчей после исправления расчёта

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S3.11](S3.11.md)

**DESC:** Как администратор лиги, я хочу пересчитать метаданные уже сохранённых матчей и итоги игроков по новым правилам, чтобы старые данные не расходились с исправленным расчётом.

**ACs:**
- [ ] `POST /migrations/recalculate-games` (только `ADMIN`) пересчитывает метаданные каждого матча, затем сезонные и карьерные итоги всех игроков, участвовавших в матчах.
- [ ] Режим `dryRun=true` ничего не пишет и возвращает, у скольких матчей и игроков значения изменятся.
- [ ] Пересчёт идемпотентен: второй запуск ничего не меняет.
- [ ] Матч, который не проходит новые правила (нет капитана, нет позиции у опубликованного), не прерывает пересчёт: он попадает в список `skipped` с причиной.
- [ ] Тест на синтетической базе: матч, посчитанный по-старому, после запуска получает верные `hasWon` для второй команды, пенальти, очки новой системы.

## Заметки

- Источник: [S3.11](S3.11.md). Метаданные матча хранятся в самом матче (`metadata.players`), поэтому `POST /players/recalculate/season` их не исправляет: он берёт сохранённые значения как есть. Нужен пересчёт самих матчей.
- Запускать до переключения на MVPS ([S6.7](../E06-data-migration/S6.7.md)) и на копии данных, прод не трогать ([AGENT.md](../../../AGENT.md)).
- Старые матчи без позиций у участников нельзя пересчитать как опубликованные: их нужно либо дополнить владельцем, либо перевести в «Черновик»; решение владельца записать здесь.
