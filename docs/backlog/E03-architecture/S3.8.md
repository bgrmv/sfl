# S3.8 — Границы слоёв клиента проверяются линтером

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S1.6](../E01-dependency-upgrades/S1.6.md)

**DESC:** Как разработчик, я хочу, чтобы линтер запрещал импорты против слоёв (например, из `shared` в `entities`), чтобы структура FSD не размывалась.

**ACs:**

- [x] Настроено правило границ (встроенный `no-restricted-imports` по слоям, без новой зависимости): `pages → features → entities → shared`.
- [x] Импорт в обратную сторону даёт ошибку линта.
- [x] Существующие нарушения исправлены.

## Заметки

- **Сделано (2026-11-16):** правила в `client/eslint.config.js` (`fsdBoundaries`): `shared` не импортирует вышележащие слои, `entities` — только вниз и только через `@x` друг у друга, `features` и `pages` не импортируют срезы своего слоя. Слой `widgets` не используется ([ADR 0016](../../adr/0016-client-fsd-layers-and-cross-imports.md)), поэтому в правиле его нет. Нарушений кроме расположения сервисов `shared/services` не было (S3.17): они перенесены в `shared/auth`, `shared/api`, `shared/lib`. Относительные импорты через границы слоёв правило не ловит; в коде их нет.
