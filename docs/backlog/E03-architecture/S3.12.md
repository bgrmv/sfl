# S3.12 — Корректные HTTP-ошибки и обработка исключений

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** [S2.4](../E02-tests-ci/S2.4.md)

**DESC:** Как разработчик, я хочу получать от API осмысленные статусы и тела ошибок, чтобы клиент мог отличать «не найдено» от «ошибки сервера», а данные не терялись молча.

**ACs:**
- [x] В `GamesService` исключения бросаются экземплярами (`new ConflictException()` и т. д.): повторный матч → 409, удаление несуществующего → 404 (C1).
- [x] `GET /players/captains` объявлен раньше `:id` и отвечает 200 (C2).
- [x] `GET /players/:id` для несуществующего игрока → 404, для неверного id → 400 (C3).
- [x] `POST /players` при ошибке бросает исключение, а не возвращает его; статус не 201 (C4).
- [x] Сервисы игроков и пользователей не возвращают `null` вместо ошибки; контроллеры отвечают корректным статусом (C5).
- [x] На `PATCH /players/:id`, `POST /players`, `GET /players` есть валидация входа (DTO), неверный `ids` и отсутствующий `user` → 400 (C6).
- [x] Глобальный фильтр исключений приводит ответы к одному формату (связь с [S3.4](S3.4.md)).
- [x] При удалении игрока снимаются ссылки в матчах или удаление блокируется с понятной ошибкой; пакетное создание игроков либо целиком, либо откатывается (B2, B3).
- [x] Тесты на каждый статус из списка.

## Заметки

- Источник: [аудит кода 2026-11-13](../../audits/code-2026-11-13.md), группы B и C.
- Валидация делается на zod ([S1.12](../E01-dependency-upgrades/S1.12.md)): новый код пиши так, чтобы схемы переехали без переписывания.
- Формат тела ответов (обёртка `data`, `ContextInterceptor`, C7) решается в [S3.4](S3.4.md).

- **Сделано 2026-11-13.** Статусы: повторный матч 409, отсутствующий матч (DELETE, PATCH, PUT) 404, битый id 400, `/players/captains` 200, отсутствующий игрок 404, дубль email 409, неверное тело `POST /players` 400, неверный `ids` 400.
- Формат ошибок один: `{ statusCode, message, error? }` плюс `issues` у валидации ([all-exceptions.filter.ts](../../../server-nest/src/shared/filters/all-exceptions.filter.ts)). Ошибки Mongoose (`CastError` → 400, `ValidationError` → 400, ключ 11000 → 409) получают свой статус; настоящий 500 не показывает внутренности клиенту. Обёртки `try/catch` в контроллерах графиков и миграции, которые пробрасывали текст исходной ошибки, убраны.
- Удаление игрока с матчами **блокируется** (409): ссылки в `statistics` и `metadata.players` снимать нельзя без пересчёта сезонов. Если нужно именно удалять, отдельная история с каскадным пересчётом.
- Пакетное создание игроков откатывается вручную (транзакции MongoDB требуют replica set): уже созданные пользователи и игроки удаляются, дубль email внутри запроса отклоняется до записи.
- Не вошло: тело успешных ответов и `ContextInterceptor` ([S3.4](S3.4.md), C7); `GET /games/:id` для отсутствующего матча по-прежнему отвечает 200 с `null` (клиент мог на это опереться, решить вместе с S3.4). Матч без капитана и пустые `metadata` в ответе создания остаются в [S3.11](S3.11.md): их тесты по-прежнему `it.fails`.
