# S3.12 — Корректные HTTP-ошибки и обработка исключений

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** [S2.4](../E02-tests-ci/S2.4.md)

**DESC:** Как разработчик, я хочу получать от API осмысленные статусы и тела ошибок, чтобы клиент мог отличать «не найдено» от «ошибки сервера», а данные не терялись молча.

**ACs:**
- [ ] В `GamesService` исключения бросаются экземплярами (`new ConflictException()` и т. д.): повторный матч → 409, удаление несуществующего → 404 (C1).
- [ ] `GET /players/captains` объявлен раньше `:id` и отвечает 200 (C2).
- [ ] `GET /players/:id` для несуществующего игрока → 404, для неверного id → 400 (C3).
- [ ] `POST /players` при ошибке бросает исключение, а не возвращает его; статус не 201 (C4).
- [ ] Сервисы игроков и пользователей не возвращают `null` вместо ошибки; контроллеры отвечают корректным статусом (C5).
- [ ] На `PATCH /players/:id`, `POST /players`, `GET /players` есть валидация входа (DTO), неверный `ids` и отсутствующий `user` → 400 (C6).
- [ ] Глобальный фильтр исключений приводит ответы к одному формату (связь с [S3.4](S3.4.md)).
- [ ] При удалении игрока снимаются ссылки в матчах или удаление блокируется с понятной ошибкой; пакетное создание игроков либо целиком, либо откатывается (B2, B3).
- [ ] Тесты на каждый статус из списка.
