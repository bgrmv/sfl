# S3.5 — Атомарное сохранение матча и пересчёта

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S3.3](../E03-architecture/S3.3.md)

**DESC:** Как администратор лиги, я хочу, чтобы сохранение матча и пересчёт статистики происходили целиком или не происходили вовсе, чтобы данные не оставались наполовину обновлёнными.

**ACs:**

- [x] Сохранение матча и обновление метаданных игроков выполняются в одной транзакции MongoDB. Atlas — уже replica set. После переноса в compose ([S6.9](../E06-data-migration/S6.9.md)) там настроен single-node replica set.
- [x] Закомментированный код в `players.transactions.ts` удалён или заменён рабочим.
- [x] Тест: при ошибке пересчёта матч не сохраняется.
- [x] Есть ручной полный пересчёт сезона для администратора (бывший AC отменённой S5.5).

## Заметки

- Реализация: `TransactionService.run(work)` ([transaction.service.ts](../../../server-nest/src/entities/statistics/transaction.service.ts)) открывает сессию и `withTransaction`; `GamesService.create/update/replace/delete` и пересчёт `PlayerMetadataService` пишут через одну `session`. Пересчёт строится заново из опубликованных матчей, поэтому идемпотентен; ошибка пересчёта карьеры больше не глотается (иначе транзакция фиксировалась бы наполовину).
- `players.transactions.ts` был удалён ещё в S11.4; здесь заменён рабочим кодом.
- Ручной пересчёт: `POST /players/recalculate/season` (список игроков) теперь транзакционный, добавлен `POST /players/recalculate/season/full` (`{ seasonId }`, все игроки сезона). Оба только для `ADMIN`, строки есть в матрице `test/api/access.test.ts`.
- Нужен replica set ([ADR 0014](../../adr/0014-mongodb-replica-set.md)). Без него при старте сервер пишет в лог ошибку, а сохранение матча отвечает 500 с понятной причиной в логе. Dev-контейнер станет replica set после пересборки (S3.23).
- Тесты: `test/api/games.atomic.test.ts`, `src/entities/statistics/transaction.service.test.ts`.
- **После ревью (2026-11-16):** внутри транзакции пересчёт останавливается на первой ошибке и пробрасывает её как есть, чтобы `withTransaction` видел `TransientTransactionError` и повторял; сбор ошибок по всем игрокам остаётся только без сессии.
- **Известное, вне этой истории:** `replace` в `GamesService` вызывает `findOneAndReplace` без `returnDocument: 'after'`, метаданные считаются по старому документу, транзакция фиксирует это атомарно, но не лечит; проверка дубля номера матча в `create` идёт вне транзакции (защищает уникальный индекс); `/players/recalculate/season/full` держит одну транзакцию на весь сезон, лимит MongoDB 60 секунд на длинных сезонах может не хватить.
