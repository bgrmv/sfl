# S3.13 — Клиент: позиция и один капитан обязательны для публикации матча

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S3.11](S3.11.md)

**DESC:** Как администратор лиги, я хочу видеть в форме матча, чего не хватает для публикации, чтобы не получать от сервера ошибку 400 после заполнения всей статистики.

**ACs:**
- [ ] Форма создания и редактирования матча не даёт сохранить матч со статусом «Опубликован», если у кого-то из участников нет позиции; ошибка называет игрока.
- [ ] Форма требует ровно одного капитана в каждой команде (сейчас проверяется только наличие, [new-game.store.ts](../../../client/src/entities/games/store/new-game.store.ts)).
- [ ] Черновик и новый матч можно сохранять без позиций.
- [ ] Ответ сервера 400 с `issues` показывается пользователю понятным текстом, а не пустой ошибкой.
- [ ] Тесты стора на каждое правило.

## Заметки

- Источник: [S3.11](S3.11.md), правила из [GLOSSARY.md](../../../GLOSSARY.md) (капитан, позиция, статус матча). Сервер уже отклоняет такие матчи ([game.dto.ts](../../../server-nest/src/entities/games/game.dto.ts)): до этой истории клиент может получить 400 при сохранении.
- Трансфер (игрок в двух командах) позицию указывает в обеих строках статистики.
