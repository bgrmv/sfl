# S3.13 — Клиент: позиция и один капитан обязательны для публикации матча

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S3.11](S3.11.md)

**DESC:** Как администратор лиги, я хочу видеть в форме матча, чего не хватает для публикации, чтобы не получать от сервера ошибку 400 после заполнения всей статистики.

**ACs:**
- [x] Форма создания и редактирования матча не даёт сохранить матч со статусом «Опубликован», если у кого-то из участников нет позиции; ошибка называет игрока.
- [x] Форма требует ровно одного капитана в каждой команде (сейчас проверяется только наличие, [new-game.store.ts](../../../client/src/entities/games/store/new-game.store.ts)).
- [x] Черновик и новый матч можно сохранять без позиций.
- [ ] Ответ сервера 400 с `issues` показывается пользователю понятным текстом, а не пустой ошибкой.
- [x] Тесты стора на каждое правило.

## Заметки

- Источник: [S3.11](S3.11.md), правила из [GLOSSARY.md](../../../GLOSSARY.md) (капитан, позиция, статус матча). Сервер уже отклоняет такие матчи ([game.dto.ts](../../../server-nest/src/entities/games/game.dto.ts)): до этой истории клиент может получить 400 при сохранении.
- Трансфер (игрок в двух командах) позицию указывает в обеих строках статистики.

- **Сделано 2026-11-13 вместе с [S1.12](../E01-dependency-upgrades/S1.12.md)**: правила берутся из общей схемы (`gameRuleViolations` в `@sfl/schemas`), сообщения называют команду и игрока (`entities/games/store/game-rules.ts`), тесты — `game-rules.spec.ts`. Сохранение блокируется существующим механизмом `errors()` стора.
- **Не сделано:** показ ответа сервера `400` с `issues`. В клиенте нет единого механизма показа ошибок (ни snackbar, ни перехватчика ответов), его нужно добавить; AC остаётся открытым, статус ❌.
