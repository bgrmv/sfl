## Заметки

- Источник: [аудит REST API](../../audits/api-rest-2026-11-15.md), группы B, C, D. Мерки: RFC 9110, RFC 9457, OpenAPI 3.x.
- Первые четыре пункта сделаны 2026-11-15 без изменения путей и форм ответов. Остальные ломают клиент: делать вместе с тестом контракта из S3.19.
- Версию API (`/rest/v1`) не вводим, пока клиент один (находка C6).
- **Сделано 2026-11-17** (сервер, клиент, тесты и документы одним коммитом):
  - Действия без `{ success: 'OK' }`: `POST /teams` возвращает созданную запись; пересчёт и смена пароля отвечают `{ ok: true, data: null }` (статус 200: клиент и обёртка не знают пустых 204).
  - Пути: `POST /players/recalculations` (было `recalculate/season`) и `POST /players/recalculations/full` (было `recalculate/season/full`); `PUT /users/:id/password` (было `POST`); `GET /charts/top-players?system=total-points|ancient&season=&limit=` вместо двух `charts/top-*`, неизвестная система даёт 400.
  - `GET /players/captains` → `GET /players?isCaptain=true` (параметр `true` отдаёт только капитанов; прежнего маршрута нет).
  - `POST /players` принимает `{ players: [...] }` (1–100 штук), а не голый массив.
  - `POST /users/test-users` (заглушка, возвращала тело) и `GET /users` (отдавал сырые документы, клиент им не пользуется) удалены; матрица `access.test.ts` и список `auth.guard.test.ts` обновлены.
  - Клиент: `PlayersService.create`/`getCaptainsPlayers`, `ChartsService`. Документы: PROJECT.md (5.1) и Blueprint.
- Описание ошибок и обёртки в OpenAPI перенесено в [S3.19](S3.19.md).
- Пункты про Swagger-схему тела `POST /players` описаны через `ApiExtraModels`; проверять вид в Swagger на dev-сервере стоит глазами.
