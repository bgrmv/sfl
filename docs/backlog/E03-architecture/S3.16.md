# S3.16 — Signal forms: пилот на одной форме

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S1.4](../E01-dependency-upgrades/S1.4.md), [S3.9](S3.9.md)

**DESC:** Как разработчик, я хочу проверить signal forms с Angular Material на одной форме, чтобы решить, как переводить остальные. Решение: [ADR 0007](../../adr/0007-signal-forms-single-store.md).

**ACs:**
- [ ] Выбрана форма для пилота (предлагается диалог редактирования игрока, `player-edit-dialog`: простая, с email и именем). Она работает на `form()` из `@angular/forms/signals`.
- [ ] Проверено совместимость с `mat-form-field`, `matInput`, сообщениями об ошибках и состоянием `touched`; найденные ограничения записаны в `## Заметки`.
- [ ] Валидация формы подключена через `validateStandardSchema` к схеме (valibot сейчас, zod после [S1.12](../E01-dependency-upgrades/S1.12.md)), либо записана причина, почему это пока невозможно.
- [ ] Тесты формы: валидные и невалидные значения, отправка, сообщения об ошибках.
- [ ] По итогам пилота составлен список остальных форм (сейчас 9 файлов с реактивными формами) с порядком и оценкой; для каждой — история по правилу 6 или решение «оставить как есть».
- [ ] `pnpm check` проходит; форма вручную проверена в браузере (выполняет владелец).

## Заметки

- Не заменяет [S3.13](S3.13.md): правила «один капитан» и «позиция при публикации» в форме матча делает S3.13 на текущих формах; после пилота их можно перенести в общую схему.
- Стор `new-game` совмещает черновик матча и правила проверки; его разбор — отдельная история по итогам пилота.
