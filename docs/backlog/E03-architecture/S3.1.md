# S3.1 — Вынести доменную логику в независимый модуль

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** L · **Зависит от:** [S2.2](../E02-tests-ci/S2.2.md), [S2.3](../E02-tests-ci/S2.3.md)

**DESC:** Как разработчик, я хочу, чтобы расчёт статистики и рейтингов был чистым TypeScript без зависимостей от NestJS и Mongoose, чтобы его можно было перенести в Edge Functions или использовать на клиенте.

**ACs:**

- [x] Расчёт метаданных игрока и матча находится в пакете `packages/domain` и экспортирует чистые функции: на вход матчи, на выход метаданные.
- [x] В пакете нет импортов `@nestjs/*`, `mongoose`, `@angular/*`.
- [x] Golden-master тесты ([S2.2](../E02-tests-ci/S2.2.md)) проходят на новом модуле.
- [x] Сервер (пока он есть) использует этот пакет вместо своих утилит.

## Заметки

Сделано:

- Пакет `packages/domain` (`@sfl/domain`, ESM, `dist/`, свой `pnpm-lock.yaml`, том `domain-node-modules` в docker-compose, `chown` в post-create, шаг `audit:domain` в `pnpm check`; `pnpm build:packages` собирает его после `@sfl/schemas`, от которого он зависит ради `EnumPlayerPosition`).
- Чистые функции: `calculateGameMetadata(game)` (счёт, результат, капитаны, MVP), `calculatePlayerGameResultMetadata(playerId, game)`, `accumulatePlayerSeasonMetadata`, `accumulatePlayerCareerMetadata`, `getPointsByPosition`, типы и значения по умолчанию (`IPlayerMetadata`, `IGameMetadata`, `METADATA_DEFAULT` и др.). Вход: обычные объекты (идентификаторы строкой или с `toString()`), выход: метаданные.
- Перенесены из сервера вместе с тестами (`git mv`): `players/utils/player-*-metadata*`, `players/constants/player-career-metadata.ts`, `games/game-metadata.test.ts` (теперь вызывает функции напрямую, а не приватные методы сервиса). Правила лиги нарушены данными (чужая команда, не один капитан) → `GameMetadataError` с кодом; сервер превращает его в прежние `InternalServerErrorException` и `BadRequestException`.
- Сервер: `GamesService` и `PlayersService` стали тонкими адаптерами (читают и пишут Mongoose, пишут лог, вызывают `@sfl/domain`); `game.schema.ts` реэкспортирует `IGameMetadata` и `IPlayerGameResultMetadata` из пакета.
- Нет импортов `@nestjs/*`, `mongoose`, `@angular/*`, `mongodb`, `express`, `rxjs`: проверяет `packages/domain/src/purity.test.ts` (входит в `pnpm check`, шаг `packages:test`).
- Поведение не изменилось: `test/golden` на настоящем анонимизированном дампе совпадает с неизменённым `golden-baseline.json`; все серверные тесты зелёные.

Осталось и оговорки:

- `charts.service.ts` — только агрегации MongoDB (`$match`, `$sort`, `$lookup`), чистого расчёта в нём нет, переносить нечего.
- Агрегации выборки игр сезона и «пересчёт всех игроков» остаются в `PlayersService` (это работа с базой); в домен ушла только свёртка.
- Покрытие домена порогом не проверяется: из `server-nest/vitest.config.ts` убран порог по `players/utils/**` (там остался только `present-player.ts`); порог на `packages/domain` можно добавить отдельно.
- `playerId`-ключи, `Date` ошибки и `new Date()` в `calculatePlayerGameResultMetadata` оставлены как были; время можно подменить третьим аргументом.
- В уже созданном dev-container нужна пересборка (новый том `domain-node-modules`, см. «Rebuild» в docs/development.md), затем `pnpm install` из корня.
