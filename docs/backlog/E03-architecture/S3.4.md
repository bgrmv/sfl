# S3.4 — Единый формат ответов API

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S2.4](../E02-tests-ci/S2.4.md)

**DESC:** Как разработчик клиента, я хочу, чтобы все ответы API имели один формат, чтобы обрабатывать данные и ошибки одинаково.

**ACs:**

- [x] Контроллеры возвращают значения, а не вызывают `res.json(...)` через `@Res()`.
- [x] Формат ответа `Result`: `{ ok: true, data }` для успеха и `{ ok: false, error: { status, code, message, issues? } }` для ошибок ([ADR 0011](../../adr/0011-result-response-format.md)).
- [x] Глобальный фильтр исключений формирует ошибки в этом формате.
- [x] Клиентские сервисы обновлены.

## Заметки

- **Сделано 2026-11-15** по решению владельца: единый тип в духе `Result<T, E>` из Rust (классы `Ok`/`Err` с `map`, `mapErr`, `andThen`, `match`, `unwrapOr`, `fromSerialized`, `fromPromise` в `@sfl/schemas`), вместо `{ data }`/`{ error }` из исходного AC. `meta` для пагинации добавится в [S10.1](../E10-product-features/S10.1.md).
- Сервер: `ResponseInterceptor`, `AllExceptionsFilter`, девять методов без `@Res()` (cookie входа через `passthrough`). Клиент: `HttpService` снимает обёртку, `toResult()` и `apiErrorMessage(ApiError)` показывают ошибку при сохранении матча ([S3.13](S3.13.md)).
- Остаётся для [S3.10](S3.10.md): общий перехватчик ошибок и уведомления. Не проверено вручную в браузере.
