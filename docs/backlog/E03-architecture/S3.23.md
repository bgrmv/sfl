# S3.23 — MongoDB как replica set (транзакции)

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** —

**DESC:** Как разработчик, я хочу, чтобы MongoDB работала как replica set из одного узла, чтобы публикация и отзыв матча выполнялись транзакцией ([ADR 0014](../../adr/0014-mongodb-replica-set.md)).

**ACs:**

- [ ] Dev-container запускает `mongo:7.0` с `--replSet rs0`, первый старт инициализирует набор (`rs.initiate()`), healthcheck ждёт состояния PRIMARY; `docs/development.md` и раздел «Rebuild» описывают изменение.
- [ ] Строка подключения содержит `replicaSet=rs0`; сервер стартует и без `directConnection`-обходов, `pnpm start:dev` работает как прежде.
- [ ] Серверные тесты используют `MongoMemoryReplSet`; пример теста с `withTransaction` (откат при ошибке) проходит.
- [ ] Скрипт бэкапа и восстановления ([S6.1](../E06-data-migration/S6.1.md)) проверен на replica set.
- [ ] План для VPS ([S6.9](../E06-data-migration/S6.9.md), [S7.2](../E07-vps-hosting/S7.2.md)): тот же образ и параметры.
- [ ] `pnpm check` проходит.
