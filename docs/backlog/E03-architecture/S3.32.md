# S3.32 — Контракт API: перенос схем, ответы успеха и имена типов

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P3 · **Размер:** L · **Зависит от:** [S3.19](S3.19.md)

**DESC:** Как разработчик, я хочу довести [S3.19](S3.19.md) до конца: все формы API в `@sfl/schemas`, ответы успеха описаны схемами, типы клиента названы по правилам [ADR 0018](../../adr/0018-openapi-from-zod-schemas.md), чтобы не осталось ручных описаний и дублей.

**ACs:**

- [ ] `UpdatePlayerDTO` и `CreatePlayersDTO` перенесены из `server-nest` в `@sfl/schemas` (на `zod/mini`), сервер и клиент берут типы оттуда; в документ OpenAPI они входят компонентами `PlayerUpdateInput` и `PlayerCreateInput`.
- [ ] Ответы успеха описаны схемами: у каждой операции `200`/`201` ссылается на компонент (обёртка `{ ok: true, data }`), классы с `@ApiProperty` (`Player`, `Team`, `Game`, `PlayerCreationDTO` и др.) удалены из контроллеров.
- [ ] Каждый домен приведён к правилам имён: типы клиента `IGameDTO`, `TPlayerFinal`, `ITeamDTO`, `TTeamFinal`, `IPlayerDTO` и подобные заменены на `Game`, `Player`, `Team` из `@sfl/schemas` (без префиксов `I` и `T`, без пустых `*Settings`); `TCaptain` выражен через игрока.
- [ ] Mongoose-схемы приводятся к доменным типам явным маппером, не отдаются в контроллерах как есть.
- [ ] Нет неиспользуемых экспортов типов в `packages/*`, `client/` и `server-nest/` (проверка knip без ложных срабатываний, [S11.4](../E11-dx-docs/S11.4.md)).
- [ ] `server-nest/openapi.json` обновлён, `pnpm check` проходит.

## Заметки

- Создана 2026-11-17 как остаток [S3.19](S3.19.md): сделана инвентаризация, ADR 0018 с правилами имён, генерация компонентов, тел матча и тела ошибки, проверка расхождений в `pnpm check`.
