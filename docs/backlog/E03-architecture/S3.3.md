# S3.3 — Разорвать цикл games ↔ players

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S3.1](../E03-architecture/S3.1.md)

**DESC:** Как разработчик, я хочу убрать циклическую зависимость между модулями матчей и игроков, чтобы модули можно было менять и тестировать отдельно.

**ACs:**

- [x] `GamesModule` не использует `forwardRef(() => PlayersModule)`.
- [x] `PlayersService` не указан в провайдерах `GamesModule`, существует один экземпляр.
- [x] Пересчёт метаданных вызывается через отдельный сервис или событие «матч опубликован».

## Заметки

Выбран отдельный сервис, а не события: `@nestjs/event-emitter` не подключён, а вызов должен остаться синхронным и дожидаемым (ответ API приходит после пересчёта, [S3.5](S3.5.md) обернёт его в транзакцию вместе с сохранением матча). Расчёт сезона и карьеры игрока (`recalculatePlayersSeasonAndCareerMetadata`) перенесён из `PlayersService` в `PlayerMetadataService` (`server-nest/src/entities/statistics/`), он зависит только от моделей `Player` и `Game`. `GamesModule` и `PlayersModule` импортируют `StatisticsModule`; `PlayersService` остался только в `PlayersModule`. Тесты: `statistics/player-metadata.service.test.ts`, `statistics/module-graph.test.ts`; golden-master и API-тесты без изменений.
