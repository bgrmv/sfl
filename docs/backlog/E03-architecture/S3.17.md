# S3.17 — Привести структуру клиента к FSD

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** L · **Зависит от:** [S3.6](S3.6.md)

**DESC:** Как разработчик, я хочу, чтобы слои клиента соответствовали FSD (страницы в `pages`, публичный API у каждого слайса, без кросс-импортов сущностей), чтобы границы можно было проверять линтером ([S3.8](S3.8.md)) и дальше менять UI по частям.

**ACs:**

- [x] Страницы из `entities/games/pages` и `entities/players/pages` перенесены в `pages/`, виджет `entities/games/widgets` — в `pages/` или `features/` по правилам skill `feature-sliced-design`; маршруты собираются в `app`.
- [x] `entities/utils` и `entities/charts` перенесены в подходящие места (`shared/lib`, `features`, `pages`); константы правил лиги из `shared/constants` не лежат в `shared` (мёртвые `MINIMUM_OF_*` удалены; `TeamEnum` остаётся, см. заметки).
- [x] У каждого слайса `features`, `widgets`, `pages`, `entities` есть `index.ts`; алиасы указывают на слайс; импортов мимо `index.ts` (сейчас 56 в `entities`) нет.
- [x] Кросс-импорты `games` ↔ `players` ↔ `teams` ↔ `captains` разорваны одной из стратегий skill (слияние границ, вынос общего, сборка в верхнем слое); решение записано в ADR.
- [x] Файлы названы по домену, а не по роли (`types.ts`, `utils.ts`, `constants.ts`).
- [x] Слайсы без потребителей (`captain-to-add`, `captains-selection`, `games-table`) удалены или подключены, решение — вместе с [S10.8](../E10-product-features/S10.8.md): по решению владельца 2026-11-16 оставлены как есть (с `index.ts` и сегментом `ui/`) до S10.8.
- [x] `pnpm check` проходит, поведение клиента не изменилось (автоматическая проверка: lint, 128 тестов, prod-сборка; ручной прогон страниц в браузере не делался).

## Заметки

- Источник: [аудит FSD](../../audits/fsd-client-2026-11-13.md).
- Делать после [S1.4](../E01-dependency-upgrades/S1.4.md) (ручная проверка страниц) и до [S3.8](S3.8.md): линтер границ на текущей структуре даст сотни ошибок.
- Не обязательно прийти к «чистому» FSD за один заход: skill допускает минимум слоёв (`app`, `pages`, `shared`) и добавление `entities`/`features` только по необходимости.
- **Первый шаг сделан (2026-11-16):** файлы `entities/games/store/*` разложены по сегментам FSD: `model/games-list/` (список матчей сезона) и `model/game-form/` (форма матча: стор, состояние `new-game.state.ts`, правила, фичи команд, игроков и статистики). Цикл «фичи ↔ стор» разорван вынесением состояния в `new-game.state.ts`, обратный импорт типа из компонента убран (`GamePlayerStatistic` теперь в `types.ts`). Остаётся: `services/` → `api/`, `components`, `pages`, `widgets` → `ui/` или слои выше, форма матча как `features/game-form` (она работает с игроками и командами, то есть по сути фича, а не сущность), кросс-импорты `players` → `games` (`players-autocomplete` берёт `NewGameStore`), барелл `index.ts` и линтер границ ([S3.8](S3.8.md)).
- **Сделано (2026-11-16, ветка `refactor/client-fsd-s3-17`):** решения в [ADR 0016](../../adr/0016-client-fsd-layers-and-cross-imports.md). Слой `widgets` убран, страницы перенесены в `pages/*` (`home`, `game-list`, `game-edit`, `game-details`, `player-list`, `player-details`, `captain-list`, `auth-sign-in`), маршруты собраны в `app/app.routes.ts`, охранник маршрута — `app/admin.guard.ts`. Выделены фичи `game-edit`, `game-delete`, `player-select` (без стора, входы и выходы; склейка с формой в `pages/game-edit/ui/team-players-autocomplete`), `player-create`, `player-edit`, `player-delete`. `entities/games` теперь без компонентов страниц; типы `game.ts` разнесены по сущностям (`players/model/player.ts`, `teams/model/team.ts`, `games/model/game-statistic.ts`), связь `games` → `players`/`teams` только через `@x`. `entities/charts` ушёл на страницу `home`, `entities/utils/date.ts` — в `shared/lib/date.ts`. Удалён мёртвый код: `getGameCards`, `isPlayerStatisticTransferable`, `mappers/game.ts`, `captains/constants.ts`, `shared/constants/{captains,players}.ts`, пустой `shared/ui/players`, неиспользуемый `players-admin-widget`. Правило ESLint `no-restricted-imports` запрещает импорт мимо `index.ts`. Тесты: `players-autocomplete` (фильтр и чипсы), `team-players-autocomplete` (выбор игрока, капитан).
- **Остаётся:** `TeamEnum` (BMW/HONDA, правило лиги) и `CardVariantEnum` в `shared/constants`; (сервисы auth и http перенесены в `shared/auth` и `shared/api` в [S3.8](S3.8.md)); страница `captains` пока без маршрута (как и до работы); линтер границ слоёв сделан в [S3.8](S3.8.md); ручная проверка страниц.
- **Именование (2026-11-16):** слайсы переименованы по маске ADR 0016: `entities` — предмет в единственном числе, `features` и `pages` — `<предмет>-<действие>` (`game-edit`, `player-select`, `captain-toggle`, `auth-sign-in`, `game-list`).
