**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**DESC:** Как разработчик, я хочу один workspace с общими типами для клиента и бэкенда, чтобы не дублировать интерфейсы вроде `IGameDTO` и не расходиться в формате данных.

- [x] Один `pnpm install` в корне ставит всё (контейнер, `post-create.sh`, `pnpm check`).

## Заметки

- **Сделано 2026-11-13.** Решение и отклонённые варианты — [ADR 0009](../../adr/0009-pnpm-workspace-separate-lockfiles.md). Пакет `@sfl/schemas` (`packages/schemas`): enum `EnumGameStatus`, `EnumPlayerPosition`, `EnumTeamColor`, `EnumPlayerStatus` и DTO `TeamDTO`, `PlayerStatisticDTO`, `PlayerUserDTO`, `PlayerDTO`, `GameDTO`. Клиент (`entities/games`, `entities/teams`) и сервер (`*.schema.ts`) берут их оттуда; повторные объявления удалены.
- **Каждый проект сохранил свой lock-файл и `node_modules`** (`shared-workspace-lockfile=false`), поэтому версии клиента и сервера не связаны и тома контейнера те же, плюс один для `packages/schemas/node_modules`. Пересборка контейнера нужна один раз (новый том).
- **Что вскрылось при объединении.** (1) У клиента был лишний статус матча `furture` (заглушка карточки будущего матча); он остался клиентским расширением общего enum. (2) Клиентский тип статистики не допускал `position: null`, а сервер допускает (черновик): теперь тип общий. (3) `playedAt` клиент объявлял `Date`, хотя по сети идёт ISO-строка: общий `GameDTO` честно хранит строку, клиент поверх него использует `Date`. (4) Для `PlayerDTO` `id`, `email` и `surname` пользователя необязательны, потому что публичный ответ их не содержит ([S8.10](../E08-security-privacy/S8.10.md)).
- **Что осталось отдельным.** Серверные типы хранения (`IGame`, `ServerPlayer`, `IGameMetadata`) остаются в `server-nest`: они про базу, а не про контракт. Типы `metadata` матча (`any` в `GameDTO`) переедут с доменным пакетом в S3.1.
- AC «CI обновлён» перенесён в [S2.1](../E02-tests-ci/S2.1.md) по решению владельца (2026-11-13): workflow в репозитории нет.
