# S3.28 — Повторяющиеся блоки клиента: вынести в `entities/*/ui` и `shared/ui/kit`

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S3.17](S3.17.md), [S3.8](S3.8.md)

**DESC:** Как разработчик, я хочу, чтобы одинаковые блоки страниц (строка игрока, строка капитана, строка матча) жили в одном месте, а не копировались в каждую страницу, чтобы правка дизайна меняла их везде сразу, а страницы по 300–700 строк стали короче.

Основание: разбор страниц 2026-11-17. Строка «аватар + имя-ссылка + подпись с номером» повторяется в `players-board` (таблица и карточки), `captains-board`, `player-board` (соперники, союзники), `compare-people`, `profile` и admin-страницах. Общие кирпичи (`sfl-form-dots`, `sfl-split-bar`, `sfl-card`, `sfl-stat`) уже в `shared/ui/kit`, не хватает блоков с предметными данными. Решение про слой `widgets` не меняется: [ADR 0016](../../adr/0016-client-fsd-layers-and-cross-imports.md).

**ACs:**

- [ ] Составлен список повторов: какой блок, в каких страницах, что в нём предметное (имя игрока, номер, счёт) и что общее. Блоки без предметных данных идут в `shared/ui/kit`, с предметными данными — в `ui/` своей сущности (`entities/player`, `entities/captain`, `entities/game`).
- [ ] Каждый вынесенный блок — отдельный компонент с входами-данными и публичным экспортом через `index.ts` слайса; ссылки на страницы игрока и матча собираются внутри блока.
- [ ] Блок, которому нужны данные двух сущностей, не создаёт кросс-импорт: получает их входами от страницы (стратегия C из ADR 0016). Если без `widgets` не обойтись, причина записывается в ADR.
- [ ] Страницы `players-board`, `captains-board`, `player-board`, `compare-people`, `profile` используют вынесенные блоки; копии разметки удалены, внешний вид не меняется (сверка с досками «Табло»).
- [ ] На каждый вынесенный блок есть тест компонента (рендер, ссылка, пустые значения).
- [ ] [ADR 0016](../../adr/0016-client-fsd-layers-and-cross-imports.md) дополнен правилом: где живёт повторяющийся блок (`shared/ui/kit` или `entities/*/ui`) и когда пересматривать вопрос о `widgets`; `pnpm check` проходит (линт границ слоёв, типы, тесты, сборка).

## Заметки

- Создано 2026-11-17 по вопросу владельца «не лишний ли слой `widgets`»: слой не нужен, повторы решаются в `entities/*/ui`.
- Делать до [S10.76](../E10-product-features/S10.76.md): новый блок противостояния капитанов должен сразу строиться на общих строках капитана и игрока.
