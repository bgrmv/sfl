# S3.28 — Повторяющиеся блоки клиента: вынести в `entities/*/ui` и `shared/ui/kit`

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S3.17](S3.17.md), [S3.8](S3.8.md)

**DESC:** Как разработчик, я хочу, чтобы одинаковые блоки страниц (строка игрока, строка капитана, строка матча) жили в одном месте, а не копировались в каждую страницу, чтобы правка дизайна меняла их везде сразу, а страницы по 300–700 строк стали короче.

Основание: разбор страниц 2026-11-17. Строка «аватар + имя-ссылка + подпись с номером» повторяется в `players-board` (таблица и карточки), `captains-board`, `player-board` (соперники, союзники), `compare-people`, `profile` и admin-страницах. Общие кирпичи (`sfl-form-dots`, `sfl-split-bar`, `sfl-card`, `sfl-stat`) уже в `shared/ui/kit`, не хватает блоков с предметными данными. Решение про слой `widgets` не меняется: [ADR 0016](../../adr/0016-client-fsd-layers-and-cross-imports.md).

**ACs:**

- [x] Составлен список повторов: какой блок, в каких страницах, что в нём предметное (имя игрока, номер, счёт) и что общее. Блоки без предметных данных идут в `shared/ui/kit`, с предметными данными — в `ui/` своей сущности (`entities/player`, `entities/captain`, `entities/game`).
- [x] Каждый вынесенный блок — отдельный компонент с входами-данными и публичным экспортом через `index.ts` слайса; ссылки на страницы игрока и матча собираются внутри блока.
- [x] Блок, которому нужны данные двух сущностей, не создаёт кросс-импорт: получает их входами от страницы (стратегия C из ADR 0016). Если без `widgets` не обойтись, причина записывается в ADR.
- [ ] Страницы `players-board`, `captains-board`, `player-board`, `compare-people`, `profile` используют вынесенные блоки; копии разметки удалены, внешний вид не меняется (сверка с досками «Табло»).
- [x] На каждый вынесенный блок есть тест компонента (рендер, ссылка, пустые значения).
- [x] [ADR 0016](../../adr/0016-client-fsd-layers-and-cross-imports.md) дополнен правилом: где живёт повторяющийся блок (`shared/ui/kit` или `entities/*/ui`) и когда пересматривать вопрос о `widgets`; `pnpm check` проходит (линт границ слоёв, типы, тесты, сборка).

## Заметки

- Создано 2026-11-17 по вопросу владельца «не лишний ли слой `widgets`»: слой не нужен, повторы решаются в `entities/*/ui`.
- Делать до [S10.76](../E10-product-features/S10.76.md): новый блок противостояния капитанов должен сразу строиться на общих строках капитана и игрока.
- **Список повторов (2026-11-17).**
  - Строка игрока «аватар + имя (ссылка) + номер»: `players-board` (таблица), `game-board` (MVP), `seasons` (топ-3), `admin-players`, `player-board` (соперники и союзники). Вынесена в `PlayerChipComponent` (`entities/player/ui`); инициалы считает она сама, копии `slice(0, 2).toUpperCase()` и `ini` на страницах убраны. Тест: `player-chip.component.spec.ts`.
  - Шапка игрока «крупный аватар + заголовок + подпись»: `player-board`, `compare-people`, `profile` («My player»), `connect`. Состав подписей у всех разный (позиция, дни, статус привязки), общего блока пока нет.
  - Карточка рейтинга «аватар + имя + число справа»: `players-board` (Cards), `captains-board` (Cards). Имя оформлено заголовком `k-head`, сверху бейдж «C»; блок остаётся в страницах.
  - Строка матча: единственная настоящая в `games-board`; остальные ссылки на матч собирает `season-ribbon`, он уже общий. Выносить нечего.
  - Кирпичи без данных (`sfl-form-dots`, `sfl-split-bar`, `sfl-card`, `sfl-stat`, `sfl-avatar`) уже в `shared/ui/kit`.
- **AC про страницы не закрыт полностью:** на `PlayerChipComponent` переведены `players-board`, `player-board`, `game-board`, `seasons`, `admin-players`. `captains-board`, `compare-people` и `profile` остались: там шапки и карточки с другой вёрсткой (см. список). Нужно решение владельца: сузить AC до сделанного или завести блок «шапка игрока» и «карточка рейтинга».
- Проверено: lint, типы, 233 клиентских теста; в браузере экраны не открывал.
