# S3.25 — Стор капитанов без дубля списка игроков

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S3.22](S3.22.md), [S3.7](S3.7.md)

**DESC:** Как разработчик, я хочу один источник правды о капитанах, чтобы список игроков и список капитанов не расходились и не загружались двумя запросами.

**Основание:** ревью 2026-11-16: `CaptainsStore` держит свой список (`players/captains`), хотя `PlayersStore` уже содержит тех же игроков и вычисляет `captains`. Рецензент-упроститель оценил выигрыш в около 50 строк; доменный пурист: если у капитанов нет своей проекции, достаточно хранить только выбор (`selected`).

**ACs:**

- [x] Проверено, нужна ли капитанам отдельная проекция (например, статистика побед из `GET players/captains` отличается от игроков). Если нужна, это `computed` поверх `PlayersStore`, а не второй независимый запрос; решение записано в заметках.
- [x] `CaptainsStore` хранит только выбор по командам (`selected`) и читает капитанов из одного источника; `toggleCaptain` меняет игрока в одном месте.
- [x] Тесты на потребителей (`captains-selection`, `captains-table`, `captains-toggle`, `captain-to-add`) написаны до правки.
- [x] `pnpm check` зелёный.

## Заметки

- Риск средний: затрагивает страницу капитанов и форму матча; без тестов на потребителей не удалять.
- **Решение по проекции (шаг 1).** Отдельная проекция не нужна. `GET players/captains` (`findCaptains`) возвращает те же документы игрока через тот же `presentPlayer`, отфильтрованные по `isCaptain: true`; единственное отличие от `GET players` — в ответ входит `metadata` (статистика), которую клиент не читает: плоские поля `totalGames`, `wonGames` и др. из `TCaptain` сервер не отдаёт (в таблице капитанов они были пустыми и остаются пустыми). Поэтому капитаны — это `PlayersStore.captains` (`computed` по коллекции игроков), второй запрос не нужен. Когда в S10.x понадобится статистика капитанов, её берут из `metadata` игроков или из отдельного маршрута статистики, а не из второго списка.
- **Что сделано.** `CaptainsStore` хранит только `selected: { id, team }[]` (методы `addSelected`, `deleteSelected`); `captains`, `captainsWithoutTeam`, `load`, `add`, `delete`, `toggleCaptain`, `CaptainsService` удалены. Потребители читают капитанов из `PlayersStore.captains`, комбинирование с выбором (`captainsWithoutTeam`, `selectedCaptain`) — в `captains-selection`; `toggleCaptain` — один раз, в `PlayersStore` (запрос, затем запись по ответу). Композиция сделана в `features`, а не через `@x`: ADR 0016 разрешает `@x` только типы и только для `game`, поэтому `entities/captain` не импортирует `entities/player`; `TCaptain` — структурный тип (игрок из `PlayersStore` подходит к нему как есть, статистика необязательна).
- **Тесты до правки (ADR 0013).** Спеки `captains-selection`, `captains-table`, `captains-toggle`, `captain-to-add` и новый `captains-store.spec.ts` написаны первыми и падали на старом коде (капитаны брались из второго источника); после правки зелёные.
- **Поведение.** Для пользователя не меняется: страница капитанов показывает тех же игроков, но вместо `GET players/captains` грузится `GET players` (один запрос, провайдеры `PlayersService`/`PlayersStore` перенесены на страницу капитанов). Переключатель в `captains-toggle` по-прежнему `[disabled]="true"`; раньше его обработчик менял только локальный список, теперь вызывает `PlayersStore.toggleCaptain` (запрос на сервер) — при включении переключателя строка уйдёт из списка капитанов. `captain-select` и `captain-add` нигде не подключены (их место займёт S10.x); в `captain-add` исправлен `toObservable` в `ngOnInit` (вне контекста внедрения, компонент падал бы при первом показе), клик по карточке теперь снимает капитана через `PlayersStore.toggleCaptain`.
- `PlayersService.getCaptainsPlayers` (`GET players/captains`) остаётся без потребителей; удалить или использовать — в [S3.17](S3.17.md) (слайсы без потребителей).
- **После ревью (2026-11-16):** `CaptainsStore` нигде не предоставлен (его давала страница капитанов); когда `captain-select` подключат к форме матча, стор должен жить на уровне формы, иначе будет `NullInjectorError`. Запись `selected` не очищается, если игрок перестал быть капитаном через `PlayersStore.toggleCaptain`: чистить при подключении компонента. Клик по карточке в `captain-to-add` теперь снимает флаг капитана на сервере (раньше только убирал карточку локально): учесть при решении S10.8.
