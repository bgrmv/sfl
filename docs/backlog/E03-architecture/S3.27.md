# S3.27 — Полный пересчёт сезона: подготовка вне транзакции

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P3 · **Размер:** S · **Зависит от:** [S3.5](S3.5.md)

**DESC:** Как администратор лиги, я хочу, чтобы полный пересчёт сезона (`POST /players/recalculate/season/full`) не упирался в лимит транзакции MongoDB в 60 секунд на длинных сезонах, оставаясь «всё или ничего» по записи.

**ACs:**

- [ ] Тест: на большом сезоне (искусственно замедленный расчёт) полный пересчёт не падает по времени транзакции и пишет всё одним `bulkWrite`; при ошибке записи не меняется ни один игрок.
- [ ] Метаданные игроков считаются на чтении без сессии (чистые функции `@sfl/domain`), в транзакции остаётся только запись.
- [ ] Перед записью проверяется, что набор опубликованных матчей сезона не изменился с начала подготовки (число и последняя метка обновления); при расхождении подготовка повторяется ограниченное число раз, потом ошибка с понятным сообщением.
- [ ] Сохранение одного матча остаётся целиком в транзакции (пересчёт читает только что записанный матч).
- [ ] `pnpm check` зелёный.

## Заметки

- Решение: вариант «подготовка вне транзакции, короткая транзакция на запись». Отвергнуты: транзакция на каждого игрока (теряется атомарность полного пересчёта) и повышение `transactionLifetimeLimitSeconds` (на Atlas не везде настраивается).
- Срочности нет, пока в сезоне десятки матчей.
