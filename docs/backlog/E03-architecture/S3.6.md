# S3.6 — Конфигурация окружений клиента

**Эпик:** 3 — Улучшение архитектуры · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** —

**DESC:** Как разработчик, я хочу понятную конфигурацию адресов и ключей клиента для каждого окружения, чтобы деплоить один и тот же код в staging и prod.

**ACs:**
- [x] Поле `API_KEY` переименовано в `apiUrl` (оно содержит URL, а не ключ).
- [x] Адреса не захардкожены в коде (`https://sfl.com:3001/rest`, `https://sfl-backend.azurewebsites.net/rest`), а подставляются при сборке из переменных окружения.
- [x] Окружения: local, preview, staging, production. Описаны в README.

- **Сделано 2026-11-13**: `client/scripts/set-env.mjs` генерирует `api-url.generated.ts` из `APP_ENV` и `API_URL`; вне `local` без `API_URL` берётся `/rest` (один origin, как в целевом монолите). Окружения описаны в README, раздел «Окружения клиента». Файл настройки `preview`/`staging`/`production` на сервере появится вместе с деплоем (P4).
