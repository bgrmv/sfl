# S11.6 — Dev-container для локальной разработки

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P0 · **Размер:** M · **Зависит от:** —

**DESC:** Как разработчик (или ИИ-агент, который работает в моём редакторе), я хочу открыть репозиторий в dev-container и сразу получить Node.js, pnpm и локальную MongoDB, чтобы запускать сервер, клиент, тесты и линтер без ручной настройки машины и без доступа к прод-базе.

**ACs:**
- [ ] В корне есть `.devcontainer/devcontainer.json` и `.devcontainer/docker-compose.yml` с двумя сервисами: `workspace` (Node.js и pnpm) и `mongodb`.
- [ ] Версия Node.js берётся из `.nvmrc`, если он уже есть ([S1.2](../E01-dependency-upgrades/S1.2.md)). Если нет — в контейнере фиксируется актуальная LTS, а S1.2 потом переносит её в `.nvmrc`. pnpm ставится через corepack.
- [ ] `postCreateCommand` ставит зависимости в `client/` и `server-nest/` (`pnpm install --frozen-lockfile`).
- [ ] Для dev-сервера создаётся `server-nest/.env` из `.env.example` ([S11.1](S11.1.md)) или из шаблона в `.devcontainer/`. `DATABASE_URL` указывает на сервис `mongodb`, секреты токенов — локальные dev-значения. Файл не попадает в git.
- [ ] HTTPS в dev работает: самоподписанный сертификат генерируется в `ssl/` при создании контейнера, а `ssl/` есть в `.gitignore`. Если к этому моменту в dev уже есть HTTP-режим, вместо сертификата используется он.
- [ ] Порты сервера (`3001`) и клиента (`4200`) проброшены. Клиент в контейнере ходит в API по адресу, который открывается из браузера на хосте.
- [ ] Есть seed-скрипт с **синтетическими** данными: несколько команд, игроков, матчей и один администратор с dev-паролем, описанным в README. Реальные данные из `_backups` не используются ([S0.5](../E00-security-hotfix/S0.5.md)). Когда появится обезличенный набор из [S11.2](S11.2.md), seed переходит на него.
- [ ] Данные MongoDB живут в именованном volume и переживают пересборку контейнера. Есть команда для сброса базы и повторного seed.
- [ ] В `customizations.vscode.extensions` перечислены нужные расширения: ESLint, Prettier, Angular Language Service, Claude Code.
- [ ] Внутри контейнера проходят `pnpm test`, `pnpm build` и `pnpm lint` в обоих пакетах.
- [ ] Проверка на живом стенде: в контейнере поднимаются сервер и клиент, администратор входит, создаёт и изменяет матч. Без токена изменяющие запросы получают `401` ([S0.1](../E00-security-hotfix/S0.1.md)).
- [ ] В корневом README есть раздел «Запуск в dev-container»: требования (Docker Desktop с WSL2 на Windows), как открыть, как сбросить базу. [S11.1](S11.1.md) ссылается на этот раздел.

## Заметки

- Dev-container нужен только для разработки и не заменяет прод-образ из [эпика 7](../E07-vps-hosting/). Если к моменту выполнения уже есть `Dockerfile` и `docker-compose.yml` из S7.x, сервис `mongodb` и переменные окружения стоит взять оттуда, а не писать заново.
- Мотивация: на машине разработчика нет Node.js, базы и запущенного клиента, поэтому AC «клиент работает как раньше» из [S0.1](../E00-security-hotfix/S0.1.md) нельзя проверить вживую.
