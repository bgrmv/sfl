# S11.6 — Dev-container для локальной разработки

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P0 · **Размер:** M · **Зависит от:** —

**DESC:** Как разработчик (или ИИ-агент, который работает в моём редакторе), я хочу открыть репозиторий в dev-container и сразу получить Node.js, pnpm и локальную MongoDB, чтобы запускать сервер, клиент, тесты и линтер без ручной настройки машины и без доступа к прод-базе.

**ACs:**
- [x] В корне есть `.devcontainer/devcontainer.json` и `.devcontainer/docker-compose.yml` с двумя сервисами: `workspace` (Node.js и pnpm) и `mongodb`.
- [x] Версия Node.js берётся из `.nvmrc`, если он уже есть ([S1.2](../E01-dependency-upgrades/S1.2.md)). Если нет — в контейнере фиксируется актуальная LTS, а S1.2 потом переносит её в `.nvmrc`. pnpm ставится через corepack.
- [x] `postCreateCommand` ставит зависимости в `client/` и `server-nest/` (`pnpm install --frozen-lockfile`).
- [x] Для dev-сервера создаётся `server-nest/.env` из `.env.example` ([S11.1](S11.1.md)) или из шаблона в `.devcontainer/`. `DATABASE_URL` указывает на сервис `mongodb`, секреты токенов — локальные dev-значения. Файл не попадает в git.
- [x] HTTPS в dev работает: самоподписанный сертификат генерируется в `ssl/` при создании контейнера, а `ssl/` есть в `.gitignore`. Если к этому моменту в dev уже есть HTTP-режим, вместо сертификата используется он.
- [x] Порты сервера (`3001`) и клиента (`4200`) проброшены. Клиент в контейнере ходит в API по адресу, который открывается из браузера на хосте.
- [ ] Есть seed-скрипт с **синтетическими** данными: несколько команд, игроков, матчей и один администратор с dev-паролем, описанным в README. Реальные данные из `_backups` не используются ([S0.5](../E00-security-hotfix/S0.5.md)). Когда появится обезличенный набор из [S11.2](S11.2.md), seed переходит на него.
- [x] Данные MongoDB живут в именованном volume и переживают пересборку контейнера. Есть команда для сброса базы и повторного seed.
- [x] В `customizations.vscode.extensions` перечислены нужные расширения: ESLint, Prettier, Angular Language Service, Claude Code.
- [ ] Внутри контейнера проходят `pnpm test`, `pnpm build` и `pnpm lint` в обоих пакетах.
- [x] Проверка на живом стенде: в контейнере поднимаются сервер и клиент, администратор входит, создаёт и изменяет матч. Без токена изменяющие запросы получают `401` ([S0.1](../E00-security-hotfix/S0.1.md)).
- [x] В корневом README есть раздел «Запуск в dev-container»: требования (Docker Desktop с WSL2 на Windows), как открыть, как сбросить базу. [S11.1](S11.1.md) ссылается на этот раздел.

## Заметки

- Dev-container нужен только для разработки и не заменяет прод-образ из [эпика 7](../E07-vps-hosting/). Если к моменту выполнения уже есть `Dockerfile` и `docker-compose.yml` из S7.x, сервис `mongodb` и переменные окружения стоит взять оттуда, а не писать заново.
- Мотивация: на машине разработчика нет Node.js, базы и запущенного клиента, поэтому AC «клиент работает как раньше» из [S0.1](../E00-security-hotfix/S0.1.md) нельзя проверить вживую.
- **Проверено 2026-10-25 на Rancher Desktop (moby, WSL2).** Контейнер поднят через `docker compose` и `post-create.sh`, так же как это делает VS Code; через само «Reopen in Container» в VS Code не открывался. Позже, в тот же день, контейнер открыт и через «Reopen in Container» в Antigravity: `post-create.sh` отработал, MongoDB доступна, seed на месте, `vitest` 3/3 и `pnpm build` проходят (подробнее — в заметках про Antigravity ниже). Результаты:
  - `post-create.sh` проходит с первого раза и повторно: при повторе `.env`, сертификат и seed пропускаются.
  - `server-nest`: `vitest` — 3/3, `pnpm build` проходит. Сервер стартует по HTTPS с dev-сертификатом и подключается к MongoDB. `sign-in` администратора, `whoami` и публичные GET работают на seed-данных.
  - `server-nest`: `pnpm lint` падает ещё до проверки кода — в `.eslintrc.js` у `@typescript-eslint/interface-name-prefix` значение `'on'`. Это задача [S1.6](../E01-dependency-upgrades/S1.6.md).
  - `client`: `pnpm build` проходит. `pnpm lint` находит 38 ошибок в существующем коде — тоже [S1.6](../E01-dependency-upgrades/S1.6.md).
  - Клиент в браузере на хосте не открывался, матч через UI не создавался. Поэтому AC «проверка на живом стенде» не отмечен.
- **Найден баг: `express` не объявлен в зависимостях `server-nest`.** `main.ts` и контроллеры импортируют `express`, но в `package.json` его нет. Раньше работало за счёт hoisting, а со строгим pnpm сервер не стартует (`Cannot find module 'express'`), и тест S0.1 на SWC тоже не загружается. В `server-nest` нужно добавить `express@^4.18.2` — та же версия, что у `@nestjs/platform-express`. Без этого сервер падает и в прод-образе [эпика 7](../E07-vps-hosting/).
- **Проверка S0.1 на этом стенде.** Код ветки S0.1 выгружен в контейнер через `git archive`, туда добавлен `express`. `vitest` — 9/9, включая 6 тестов матрицы доступа. На живом сервере без токена 14 закрытых маршрутов отвечают `401`, публичные GET — `200`. С токеном администратора и с одной refresh-cookie запрос проходит.
- **Попутно найдено.** `POST /games` с пустым телом даёт `500` вместо `400` — это [S0.3](../E00-security-hotfix/S0.3.md). `GET /players/captains` даёт `500`: вероятно, `@Get(':id')` объявлен раньше `@Get('captains')`.
- **Находки при запуске, уже исправлены.**
  - В образе есть глобальный pnpm 10 из npm, и он стоит в PATH раньше corepack — удаляется в `post-create.sh`.
  - corepack сам дописывал `packageManager` в `package.json` — отключено через `COREPACK_ENABLE_AUTO_PIN=0`.
  - pnpm клал store в корень репозитория — вынесен в volume `pnpm-store`, а `.pnpm-store/` добавлен в `.gitignore`.
- **Node.js 22** зафиксирован образом `javascript-node:1-22-bookworm`: `.nvmrc` пока нет. **pnpm 9.12.3** закреплён в `post-create.sh` до S1.2.
- **Seed без матчей.** Метаданные матча (`metadata` матча и игроков) считает сервер при `POST /games`. Если записывать матчи прямо в базу, пришлось бы дублировать этот расчёт, поэтому матчи создаются через клиент — и это та самая проверка из S0.1. AC про seed остаётся неотмеченным, пока команда не решит: допустимо ли так или нужен скрипт, который создаёт матчи через API.
- **Клиентские тесты.** `ng test` (Karma) требует Chrome, которого в образе нет. Либо добавить Chrome в образ, либо дождаться перехода клиентских тестов на другой раннер ([S2.1](../E02-tests-ci/S2.1.md)).
- **Lockfile после S0.1.** В ветке S0.1 `server-nest/package.json` получил `unplugin-swc` и `@swc/core` без обновления `pnpm-lock.yaml`. Без правки `pnpm install --frozen-lockfile` в `post-create.sh` падал. Исправлено 2026-11-12 при слиянии: `pnpm install --lockfile-only` в `server-nest/`, lockfile закоммичен.
- **Домен.** Клиент ходит в `https://sfl.com:3001/rest` (`client/src/environments/environment.ts`), поэтому на хосте нужна запись `127.0.0.1 sfl.com` в hosts. Это описано в README.
- **Antigravity (проверено 2026-10-25).** Встроенное расширение `antigravity-dev-containers` не умеет пересобирать контейнер: команды Rebuild нет, пересборка делается вручную (раздел «Rebuild» в README). Пересборка нужна только при изменении образа, `features`, сервиса `workspace` в compose или `post-create.sh`; для `settings` достаточно Reload Window, для зависимостей — `pnpm install`.
- **Antigravity: расширения из `customizations.vscode.extensions` не ставятся.** При создании контейнера установились 2 из 6 (Angular Language Service и Claude Code), остальные нет. Список расширен до 10 (добавлены EditorConfig, HTMLHint, DotENV, Draw.io), недостающие поставлены через CLI редактора (`antigravity-ide --install-extension`, он лежит в `~/.antigravity-ide-server/bin/*/bin/remote-cli/`). Автоматизировать можно через `postAttachCommand`, который доустанавливает отсутствующие расширения; пока не сделано.
- **Часы VM WSL2 уходят.** После сна Windows время в контейнере отставало на ~5 часов, из-за чего TLS-подключение к Atlas падало с `certificate is not yet valid`, а mongoose показывал вводящее в заблуждение «IP whitelist». Контейнер не может менять системное время; чинится на хосте через `wsl -d rancher-desktop -u root date -u -s …` или `wsl --shutdown`. Описано в Troubleshooting README.
- **Копия прода в локальной базе (2026-11-12).** Пока нет обезличенного набора ([S11.2](S11.2.md)), для разработки используется дамп прод-базы из Atlas: `.devcontainer/db-dump.cjs` (база в Atlas называется `prod`) и `.devcontainer/db-restore.cjs --drop`. Дамп лежит в `_dumps/`, который в `.gitignore`. Загружено: 16 матчей, 232 игрока, 233 пользователя, 2 команды, 2 роли. Seed-пользователи после этого заменены реальными, так что вход под `admin@sfl.local` не работает. В дампе реальные email и хеши паролей: его нельзя коммитить и передавать. Для выгрузки нужен отдельный пользователь Atlas с ролью `Read any database`. Процедура описана в README, раздел «Working with a copy of prod data».
- **Что ещё не сделано.** Флаг `--anonymize` для `db-restore.cjs` (замена email и хешей паролей при загрузке) — станет основой S11.2. Живая проверка стенда (сервер, клиент, вход администратора, создание матча) на реальных данных не выполнялась. Всё по S11.6 пока не закоммичено: `.devcontainer/`, README, `.gitattributes` и правки бэклога лежат в рабочей копии ветки `feat/s11.6-devcontainer`.
- **Прогон test/build/lint (2026-11-12, `main` без ветки S0.1).**
  - `server-nest`: `vitest run` — 3/3, `nest build` проходит, `eslint` падает на конфиге (см. выше, [S1.6](../E01-dependency-upgrades/S1.6.md)).
  - `client`: `ng build` (production) проходит; `ng lint` прошёл 38 ошибок в существующем коде (мёртвый код, пустые методы, `alt` у картинок, префиксы селекторов), после правок проходит чисто; `ng test` не запускается: в образе нет Chrome. Пока AC не выполнен — пункты ждут [S1.6](../E01-dependency-upgrades/S1.6.md) (линт `server-nest`) и [S2.5](../E02-tests-ci/S2.5.md) (клиентские тесты).
- **Живая проверка (2026-11-12, после слияния S0.1).** Администратор входит, матч создаётся (`POST /games` → 201), изменяется (`PATCH` → 200) и удаляется (`DELETE` → 200). Без токена `POST`, `PATCH`, `PUT`, `DELETE` и `GET /players/recalculate/season` дают 401, публичные `GET /games` и `GET /teams` — 200. До слияния ветки `fix/s0.1-auth-guard` анонимный `POST /games` возвращал 201.
  - Создание и удаление матча оставляют в `players.metadata.bySeason` пустую запись сезона матча (проверено на сезоне 2099, 20 игроков). Это находка для [S11.9](S11.9.md) и [S3.5](../E03-architecture/S3.5.md); запись убрана вручную.
- **Локальный администратор.** Для живой проверки в локальной базе создан `dev-admin@sfl.local` (пароль в `client/src/environments/environment.ts`). В seed его нет; при `db-restore --drop` пользователь пропадёт.
