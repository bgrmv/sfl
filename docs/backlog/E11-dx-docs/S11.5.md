# S11.5 — AGENT.md: инструкции для ИИ-агентов

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P0 · **Размер:** S · **Зависит от:** —

**DESC:** Как разработчик, который работает вместе с ИИ-агентом (Claude Code, Copilot и другими), я хочу один файл AGENT.md с правилами проекта, чтобы агент сразу понимал структуру, команды и порядок работы с бэклогом и не повторял типичные ошибки.

**ACs:**
- [ ] В корне есть `AGENT.md`. В нём кратко, со ссылками вместо пересказа:
  - назначение проекта и структура папок (`client/`, `server-nest/`, `docs/backlog/`, позже `supabase/`, `packages/`);
  - команды для каждого пакета: установка, запуск, линт, проверка типов, тесты, сборка;
  - соглашения: слои FSD на клиенте, valibot для валидации, `@ngrx/signals` для состояния, стиль коммитов `feat:` / `fix:` / `chore:` как в истории git;
  - запреты: не коммитить секреты, `.env`, бэкапы и персональные данные; не трогать прод-базу; не делать force-push в `main`;
  - definition of done: ACs выполнены, линт, типы и тесты проходят, документация обновлена.
- [ ] В AGENT.md есть раздел «Работа с бэклогом»:
  - как выбрать следующую историю: первая ❌ в [индексе](../README.md) с наивысшим приоритетом, у которой все зависимости ✅;
  - как закрыть историю: отметить ACs в файле истории, поменять ❌ на ✅ в индексе в том же PR;
  - что делать, если AC невыполним: не отмечать его, описать причину в файле истории;
  - новая работа оформляется новой историей в нужной папке эпика и строкой в индексе.
- [ ] Claude Code подхватывает файл: в корне есть `CLAUDE.md` с импортом `@AGENT.md` и без дублирования содержимого.
- [ ] Для других агентов (например, `.github/copilot-instructions.md` или `AGENTS.md`) — короткие файлы со ссылкой на `AGENT.md`, без копии текста.
- [ ] Порядок в файле поддерживается:
  - AGENT.md обновляется в том же PR, где меняются команды, структура или соглашения;
  - в шаблоне PR есть пункт «нужно ли обновить AGENT.md»;
  - в конце каждой фазы дорожной карты файл проверяется, устаревшее удаляется.
- [ ] Длина не больше ~200 строк. Подробности — в README, blueprint и ADR по ссылкам.
- [ ] Проверка: новая сессия агента без дополнительного контекста по одному AGENT.md правильно запускает тесты клиента и сервера и называет следующую историю к выполнению.
