# S11.12 — EditorConfig и единые окончания строк

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** —

**DESC:** Как разработчик, я хочу, чтобы редактор и git одинаково обрабатывали отступы и окончания строк, чтобы в диффах не было шума от CRLF/LF.

**ACs:**
- [x] `.editorconfig` лежит в корне (перенесён из `client/`), с `end_of_line = lf`.
- [x] `.gitattributes` содержит `* text=auto eol=lf`, правила для `*.sh` и `.devcontainer/**` заменены общим.
- [x] Рабочая копия приведена к LF: `git ls-files --eol` не показывает `w/crlf` и `w/mixed`, содержимое файлов не менялось (`git add --renormalize .` ничего не добавил, кроме двух конфигов).
- [ ] Prettier и ESLint не конфликтуют с `.editorconfig` (проверить в [S1.6](../E01-dependency-upgrades/S1.6.md), где настраивается Prettier; при необходимости задать `endOfLine: "lf"`).

## Заметки

- **Сделано 2026-11-12.** До правки в индексе везде был LF, а в рабочей копии у 397 файлов CRLF из-за `core.autocrlf=true` на хосте. Из-за этого git предупреждал о замене LF на CRLF при каждом коммите.
- Последний AC зависит от S1.6, поэтому статус остаётся ❌.
