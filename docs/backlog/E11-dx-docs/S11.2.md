# S11.2 — Анонимизированные тестовые данные

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** [S6.1](../E06-data-migration/S6.1.md)

**DESC:** Как разработчик, я хочу реалистичные, но обезличенные данные для локальной разработки и тестов, чтобы не работать с реальными персональными данными.

**ACs:**

- [x] Скрипт делает из прод-бэкапа набор, где имена, email и пароли заменены. Никнеймы и статистика сохраняют структуру.
- [x] Один и тот же набор используется для seed (локально и в staging) и для golden-master тестов ([S2.2](../E02-tests-ci/S2.2.md)).
- [x] Набор не содержит хешей реальных паролей.

## Заметки

- До появления обезличенного набора разработка идёт на локальной копии прода: `.devcontainer/db-dump.cjs` и `db-restore.cjs` из [S11.6](S11.6.md) уже умеют выгружать базу из Atlas и загружать её локально. Дамп лежит в `_dumps/` (в `.gitignore`) и содержит реальные email и хеши паролей.
- Скрипт обезличивания логично сделать флагом `--anonymize` у `db-restore.cjs`: он заменяет email на `user<N>@example.test`, а хеши паролей на хеш dev-пароля, остальное оставляет как есть. Тогда этот же набор можно положить в seed и в golden-master тесты ([S2.2](../E02-tests-ci/S2.2.md)).
- Состав прод-базы на 2026-11-12: 16 матчей, 232 игрока, 233 пользователя, 2 команды, 2 роли.
- **Сделано 2026-11-15** на выгрузке `_dumps/prod-2026-11-12` (владелец разрешил запускать скрипт на ней; содержимое я не читал). Скрипт [.devcontainer/anonymize-dump.cjs](../../../.devcontainer/anonymize-dump.cjs): имена, email, аватары, возраст, никнеймы (`Player<N>`), хеши паролей (хеш `dev`, у первого `ADMIN` — `admin@sfl.local` / `admin`) заменены, текст матчей (`link`, `description`, `notes`, старое поле `note`) очищен, неизвестные поля пользователя не копируются. Проверка утечек сравнивает выход со всеми личными значениями входа (967 значений, найдено 0). Результат — `_dumps/prod-2026-11-12-anonymized/`, в git не добавлен: сначала владелец смотрит сам.
- **Seed в staging** появится вместе со staging ([S7.2](../E07-vps-hosting/S7.2.md), P4): набор тот же, `db-restore.cjs`.
- **Отступление от заметки выше:** скрипт отдельный (`anonymize-dump.cjs`), а не флаг `--anonymize` у `db-restore.cjs`: так обезличенный набор можно сохранить и проверить до загрузки.
