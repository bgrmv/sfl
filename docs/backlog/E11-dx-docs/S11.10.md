# S11.10 — Аудит безопасности

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** [S11.8](S11.8.md)

**DESC:** Как администратор лиги, я хочу получить отчёт об уязвимостях в аутентификации, правах доступа и обработке данных, чтобы закрыть их до переезда на MVPS.

**ACs:**
- [ ] Аудит выполнен выбранными в [S11.8](S11.8.md) skills по `server-nest` и `client`. Агент не правит исходники.
- [ ] Проверены как минимум: вход и выдача токенов, хранение и проверка паролей, guards и роли на каждом контроллере, валидация входных данных, CORS, cookie, заголовки, логирование, зависимости с известными уязвимостями, секреты в репозитории и истории git.
- [ ] Отчёт лежит в `docs/audits/security-YYYY-MM-DD.md`. Каждая находка: файл и строка, сценарий атаки, серьёзность, предлагаемое исправление.
- [ ] Известные находки либо есть в отчёте, либо есть история на них: пароль и email пишутся в лог открытым текстом в `AuthService.signIn`, пароли хешируются SHA-512 без соли ([S8.7](../E08-security-privacy/S8.7.md)), у части пользователей в базе хеши другой длины (гипотеза, нужна проверка).
- [ ] Высокие находки проверены вручную. Для каждой заведена история с приоритетом не ниже P1 или есть решение «принимаем риск» с причиной.
- [ ] Отчёт не содержит секретов и персональных данных. Примеры эксплуатации даны на локальных синтетических данных.
- [ ] Отчёт сверен с [S8.3](../E08-security-privacy/S8.3.md): то, что можно проверять автоматически, переходит в CI, остальное остаётся ручным аудитом.

## Заметки

- Проверки выполняются только на локальной копии. Прод-Atlas и боевые адреса не трогаем.
