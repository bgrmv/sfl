# S11.10 — Аудит безопасности

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** [S11.8](S11.8.md)

**DESC:** Как администратор лиги, я хочу получить отчёт об уязвимостях в аутентификации, правах доступа и обработке данных, чтобы закрыть их до переезда на MVPS.

**ACs:**
- [x] Аудит выполнен выбранными в [S11.8](S11.8.md) skills по `server-nest` и `client`. Агент не правит исходники.
- [x] Проверены как минимум: вход и выдача токенов, хранение и проверка паролей, guards и роли на каждом контроллере, валидация входных данных, CORS, cookie, заголовки, логирование, зависимости с известными уязвимостями, секреты в репозитории и истории git.
- [x] Отчёт лежит в `docs/audits/security-YYYY-MM-DD.md`. Каждая находка: файл и строка, сценарий атаки, серьёзность, предлагаемое исправление.
- [x] Известные находки либо есть в отчёте, либо есть история на них: пароль и email пишутся в лог открытым текстом в `AuthService.signIn`, пароли хешируются SHA-512 без соли ([S8.7](../E08-security-privacy/S8.7.md)), у части пользователей в базе хеши другой длины (гипотеза, нужна проверка).
- [x] Высокие находки проверены вручную. Для каждой заведена история с приоритетом не ниже P1 или есть решение «принимаем риск» с причиной.
- [x] Отчёт не содержит секретов и персональных данных. Примеры эксплуатации даны на локальных синтетических данных.
- [x] Отчёт сверен с [S8.3](../E08-security-privacy/S8.3.md): то, что можно проверять автоматически, переходит в CI, остальное остаётся ручным аудитом.

## Заметки

- Проверки выполняются только на локальной копии. Прод-Atlas и боевые адреса не трогаем.
- Отчёт: [security-2026-11-13.md](../../audits/security-2026-11-13.md). Это дельта к [аудиту кода S11.9](../../audits/code-2026-11-13.md): роли, mass assignment, email, хеширование и `localStorage` описаны там (S8.9, S8.10, S8.7, S3.10).
- Высоких новых находок нет. Высокие из S11.9 (D1–D4) закрыты историями S8.9 и S8.10 (P1). Утечка секретов и бэклапов в историю git (I2) — решение владельца 2026-11-13: риск принят, ротация в [S0.7](../E00-security-hotfix/S0.7.md) (P4).
- Новые истории: [S8.11](../E08-security-privacy/S8.11.md), [S8.12](../E08-security-privacy/S8.12.md) (обе P2). Остальное вошло в S1.7, S8.4.
- Пункт про пароль и email в логе `AuthService.signIn` не воспроизведён: метод логирует только объект ошибки. Гипотеза про хеши другой длины не проверена, перенесена в S8.7.
