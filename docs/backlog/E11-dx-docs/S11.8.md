# S11.8 — Подбор agent skills для аудитов и дизайна

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S11.5](S11.5.md)

**DESC:** Как разработчик, я хочу выбрать несколько проверенных agent skills для аудитов кода и для дизайна, чтобы серия аудитов ([S11.9](S11.9.md), [S11.10](S11.10.md), [S11.11](S11.11.md)) и работа над темой ([S10.11](../E10-product-features/S10.11.md)) шли по одним правилам и давали сравнимый результат.

**ACs:**
- [ ] Составлен короткий список кандидатов (не больше 8): встроенные команды Claude Code (`/code-review`, `/security-review`, `/simplify`) и сторонние skills для аудитов и дизайна. Для каждого записано: что делает, откуда взят, чем отличается от соседних.
- [ ] Каждый сторонний skill прочитан целиком до установки. В `docs/skills.md` записаны источник и версия (коммит или тег). Skill с командами, которые ходят в сеть или меняют файлы вне репозитория, не принимается.
- [ ] Выбраны skills для аудитов (минимум по одному на код, безопасность и доступность) и 2–3 skills для дизайна. Для каждого выбранного записано, для какой истории он нужен.
- [ ] Выбранные skills лежат в репозитории (`.claude/skills/`) и ставятся в dev-container ([S11.6](S11.6.md)) без ручных шагов. Если часть из них личная, это явно записано в `docs/skills.md`.
- [ ] В `docs/skills.md` описаны правила аудита: агент только читает код, пишет отчёт в `docs/audits/` и не правит исходники. Найденные проблемы оформляются историями по правилу 6 из [README](../README.md).
- [ ] AGENT.md ([S11.5](S11.5.md)) ссылается на `docs/skills.md`.

## Заметки

- Кандидаты для проверки (не проверены, список надо подтвердить при выполнении): `frontend-design` и `theme-factory` из репозитория `anthropics/skills`.
- Сторонний skill — это инструкции для агента, который работает с репозиторием и терминалом. Поэтому его читают как код и фиксируют версию, а не ставят из «последней».
