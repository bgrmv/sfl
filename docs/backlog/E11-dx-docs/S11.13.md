# S11.13 — Уязвимость picomatch ломает `pnpm check`

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** —

**DESC:** Как разработчик, я хочу, чтобы `pnpm check` проходил, а шаг `pnpm audit` оставался включённым, чтобы агент и хук снова могли доверять «зелёному» результату.

**ACs:**

- [ ] Выяснено, какие пакеты тянут `picomatch <=4.0.7` (GHSA-fc5q-39xc-vjpf, ReDoS, high): по `pnpm audit` это `@angular/build` → `@vitejs/plugin-basic-ssl` → `vite`, всего 110 путей. Проверено, затрагивает ли это прод-код или только dev-инструменты.
- [ ] Когда выйдет исправленная версия `picomatch`, она закреплена через `overrides` в `pnpm-workspace.yaml` (или обновлён родительский пакет), `pnpm audit --audit-level high` проходит во всех пакетах workspace.
- [ ] Пока патча нет: шаги `audit:*` добавлены в `KNOWN` в [scripts/check.mjs](../../../scripts/check.mjs) с причиной и ссылкой на эту историю, остальные шаги `pnpm check` проходят. Запись из `KNOWN` удалена после исправления.
- [ ] `pnpm check` проходит целиком.

## Заметки

- **Найдено 2026-11-18** при закрытии [S6.1](../E06-data-migration/S6.1.md). На чистом дереве (без правок) `pnpm audit --audit-level high` падает так же: к S6.1 это не относится. В отчёте «Patched versions: `<0.0.0`», то есть исправления пока нет.
