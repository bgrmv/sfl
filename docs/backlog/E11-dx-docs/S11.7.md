# S11.7 — Pre-commit хуки: husky и lint-staged

**Эпик:** 11 — DX, документация, чистота репозитория · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S1.6](../E01-dependency-upgrades/S1.6.md)

**DESC:** Как разработчик, я хочу, чтобы при коммите изменённые файлы автоматически форматировались Prettier и проверялись ESLint, чтобы в PR не попадали ошибки стиля и линтера и ревью шло по сути.

**ACs:**
- [ ] `husky` и `lint-staged` установлены в корневом `package.json`. Если pnpm workspace ([S3.2](../E03-architecture/S3.2.md)) ещё не сделан, корневой `package.json` минимальный: только хуки и скрипт `prepare`.
- [ ] `pre-commit` запускает `lint-staged` только по staged-файлам: `prettier --write` для `*.{ts,html,scss,json,md}`, `eslint --fix` для `*.ts`. Используются конфиги из [S1.6](../E01-dependency-upgrades/S1.6.md), каждый пакет проверяется своим конфигом.
- [ ] Если ESLint находит ошибку, которую не исправить автоматически, коммит отклоняется.
- [ ] Хуки ставятся сами после `pnpm install` (скрипт `prepare`), в том числе в dev-container ([S11.6](S11.6.md)).
- [ ] Обычный коммит из нескольких файлов проходит хук быстрее 10 секунд.
- [ ] Хуки не заменяют CI: те же проверки по всему коду выполняются в [S2.1](../E02-tests-ci/S2.1.md).
- [ ] README и AGENT.md ([S11.5](S11.5.md)) описывают хуки и запрещают обходить их через `--no-verify` без причины в описании PR.

## Заметки

- Хуки зависят от S1.6 сознательно: если настроить их под текущие `.eslintrc.*`, после перехода на flat config их придётся переделывать.
