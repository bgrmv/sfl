# S7.10 — Staging закрыт от посторонних, свой пароль администратора

**Эпик:** 7 — Хостинг на VPS · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S7.6](S7.6.md)

**DESC:** Как владелец, я хочу, чтобы staging не был открыт всему интернету и в нём не было известных паролей, чтобы тестовый стенд не стал дырой в защите.

**ACs:**

- [x] В [deploy/caddy/sfl.caddy](../../../deploy/caddy/sfl.caddy) блок staging закрыт Basic Auth (`basic_auth`); хеш пароля берётся из переменной окружения Caddy (`/opt/edge/.env`), в git нет ни пароля, ни хеша. `/rest/version` остаётся доступным для проверки деплоя или проверка идёт с логином.
- [x] `.devcontainer/seed.cjs` берёт email и пароль администратора из `SEED_ADMIN_EMAIL` и `SEED_ADMIN_PASSWORD` (по умолчанию как сейчас для dev); тест или проверка, что на непустой базе seed ничего не делает.
- [x] Команда запуска seed на `sfl_staging` описана в [runbook деплоя](../../runbooks/deploy-github-mvps.md) (адрес Atlas, временный IP в Network Access, запрет `--reset`).
- [ ] На staging нет пользователя `admin@sfl.local` с паролем `admin` или `dev`.

## Заметки

- Создано 2026-11-18 по итогам первого деплоя на staging. На staging `STAGE=staging`, поэтому автоматический администратор `DevAdminSeeder` не создаётся, база после первого деплоя пуста.
