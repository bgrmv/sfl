# S7.9 — Общий edge-прокси для нескольких проектов на VPS

**Эпик:** 7 — Хостинг на VPS · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S7.7](../E07-vps-hosting/S7.7.md)

**DESC:** Как владелец сервера, я хочу держать на одном VPS несколько независимых проектов за одним прокси, чтобы платить за один сервер и добавлять новый проект без изменения существующих.

**ACs:**
- [ ] Раскладка на сервере: `/opt/edge/` — общий прокси, `/opt/<проект>/<окружение>/` — проекты. SFL живёт в `/opt/sfl/prod/` и `/opt/sfl/staging/`. У каждой папки свой `docker-compose.yml` и `.env`.
- [ ] `/opt/edge/` поднимает один Caddy, который слушает 80 и 443 и выпускает сертификаты. Это единственный контейнер на сервере с портами наружу.
- [ ] Создана внешняя Docker-сеть `edge`. Проекты подключают к ней только свой веб-сервис, а базы остаются во внутренней сети проекта.
- [ ] Главный `Caddyfile` содержит только глобальные настройки и `import sites/*.caddy`. Каждый проект кладёт свой файл маршрутов (для SFL — `deploy/caddy/sfl.caddy` из репозитория, [S7.3](../E07-vps-hosting/S7.3.md)). Подключение проекта не требует правок в чужих файлах.
- [ ] Перезагрузка конфигурации (`caddy reload`) не обрывает соединения других проектов. Ошибка в файле одного проекта отлавливается `caddy validate` до перезагрузки.
- [ ] Конфигурация edge хранится в git. Пока на сервере один проект, она лежит в `infra/edge/` этого репозитория. С появлением второго проекта её переносят в отдельный infra-репозиторий.
- [ ] В runbook описано, как добавить новый проект: папка, сеть `edge`, файл маршрутов, DNS.
