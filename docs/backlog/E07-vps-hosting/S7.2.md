# S7.2 — Docker Compose для staging и prod

**Эпик:** 7 — Хостинг на VPS · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S7.1](../E07-vps-hosting/S7.1.md), [S4.1](../E04-migration-design/S4.1.md)

**DESC:** Как разработчик, я хочу описать стек SFL одним compose-файлом в репозитории, чтобы поднимать staging и prod одной командой, не настраивать сервер руками и не мешать другим проектам на том же VPS.

**ACs:**
- [ ] `docker-compose.yml` с сервисом `app`. Сначала база — MongoDB Atlas через `DATABASE_URL`, сервис `mongodb` добавляется позже в [S6.9](../E06-data-migration/S6.9.md). Своего прокси нет: снаружи проект доступен через общий edge-прокси ([S7.9](../E07-vps-hosting/S7.9.md)).
- [ ] Nest внутри контейнера слушает обычный HTTP, TLS завершает Caddy. HTTPS-ветка и чтение сертификатов в `main.ts` удалены (локальные сертификаты из [S0.6](../E00-security-hotfix/S0.6.md) больше не нужны).
- [ ] Staging и prod ходят в разные базы Atlas (или хотя бы в разные `DATABASE_DB`). Staging никогда не пишет в прод-базу.
- [ ] Ни один сервис не публикует порты на хост. `app` подключён к внешней сети `edge` и к внутренней сети проекта, `mongodb` — только к внутренней.
- [ ] Изоляция от соседних проектов: имя compose-проекта задано явно (`sfl-prod`, `sfl-staging`), поэтому контейнеры, сети и volume не пересекаются по именам. `container_name` не используется.
- [ ] У каждого сервиса лимиты памяти и CPU (`deploy.resources.limits`). Node ограничен через `--max-old-space-size`, кеш MongoDB — через `--wiredTigerCacheSizeGB`. Лимиты подобраны по замерам из [S4.1](../E04-migration-design/S4.1.md).
- [ ] Staging и prod запускаются из одного шаблона с разными `.env` в `/opt/sfl/staging/` и `/opt/sfl/prod/`. Staging работает на анонимизированных данных ([S11.2](../E11-dx-docs/S11.2.md)).
- [ ] У сервисов есть `healthcheck` и `restart: unless-stopped`.
- [ ] Секреты лежат только в `.env` на сервере и в GitHub Secrets. В репозитории — `.env.example` без значений.
- [ ] Для локальной разработки есть override-файл (`docker-compose.local.yml`) с публикацией порта `app` и без сети `edge`: `docker compose up` поднимает весь стек на машине разработчика.
