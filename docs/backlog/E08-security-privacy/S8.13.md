# S8.13 — Вход через Google и привязка аккаунта к игроку

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P3 · **Размер:** L · **Зависит от:** [S8.9](S8.9.md), [S8.10](S8.10.md), [S4.3](../E04-migration-design/S4.3.md)

**DESC:** Как игрок, я хочу войти через аккаунт Google по ссылке от администратора, чтобы не хранить пароль в лиге, а мой email не был виден другим.

**ACs:**

- [ ] Администратор генерирует для игрока одноразовую ссылку-приглашение со сроком жизни; ссылка привязывает вошедший аккаунт Google к игроку (по id игрока) и перестаёт работать.
- [ ] После привязки email учётной записи заменяется email из Google, не отдаётся ни одним публичным эндпоинтом, пароль лиги больше не используется (сброс и смена пароля идут через Google).
- [ ] Как убедиться, что ссылку открыл именно этот игрок: способ передачи (личный канал) и срок жизни записаны в ADR; повторная привязка к другому игроку невозможна.
- [ ] Старые учётные записи с паролем ([S8.7](S8.7.md), [S4.3](../E04-migration-design/S4.3.md)) переводятся на привязку без потери статистики.
- [ ] Вход через Google проверяется на сервере (проверка токена, `state`, `nonce`), токены сессии по правилам [S8.12](S8.12.md); тесты прав доступа добавлены в `test/api/access.test.ts`.
- [ ] Персональные данные учтены по [S8.4](S8.4.md).

## Заметки

- Источник: решение владельца 2026-11-13 ([дизайн-бриф](../../design/brief.md)): пока связь по id, в будущем Google OAuth, ссылку генерирует и отправляет администратор.
