# S8.13 — Вход через Google и привязка аккаунта к игроку

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P3 · **Размер:** L · **Зависит от:** [S8.9](S8.9.md), [S8.10](S8.10.md), [S4.3](../E04-migration-design/S4.3.md)

**DESC:** Как игрок, я хочу войти через аккаунт Google по ссылке от администратора, чтобы не хранить пароль в лиге, а мой email не был виден другим.

**ACs:**

- [x] Администратор генерирует для игрока одноразовую ссылку-приглашение со сроком жизни; ссылка привязывает вошедший аккаунт Google к игроку (по id игрока) и перестаёт работать.
- [x] После привязки email учётной записи заменяется email из Google, не отдаётся ни одним публичным эндпоинтом, для подключённого Google пароль лиги не используется (сброс и смена идут через Google). Запасной вход по логину и паролю по той же ссылке для игроков без подходящей почты вынесен в [S10.48](../E10-product-features/S10.48.md).
- [x] Как убедиться, что ссылку открыл именно этот игрок: способ передачи (личный канал) и срок жизни записаны в ADR; повторная привязка к другому игроку невозможна.
- [x] Старые учётные записи с паролем ([S8.7](S8.7.md), [S4.3](../E04-migration-design/S4.3.md)) переводятся на привязку без потери статистики.
- [x] Вход через Google проверяется на сервере (проверка токена, `state`, `nonce`), токены сессии по правилам [S8.12](S8.12.md); тесты прав доступа добавлены в `test/api/access.test.ts`.
- [x] Персональные данные учтены по [S8.4](S8.4.md).

## Заметки

- Источник: решение владельца 2026-11-13 ([дизайн-бриф](../../design/brief.md)): пока связь по id, в будущем Google OAuth, ссылку генерирует администратор и передаёт лично (решение 2026-11-15: сайт писем не отправляет, потому что адреса заранее неизвестны; пока только Google, запасной путь логин и пароль с аватаром).
- **Схема входа (2026-11-18):** перенаправление на страницу Google с кодом авторизации, `state`, `nonce` и PKCE, обмен кода на сервере; скрипт Google Identity Services на наших страницах не подгружаем. Так на сайте не появляются сторонние cookies и скрипты, и баннер согласия ради входа не нужен ([S8.16](S8.16.md)). Решение записать в ADR.

- **Сделано 2026-11-18** ([ADR 0021](../../adr/0021-google-sign-in-by-redirect-and-invitation-link.md)).
  - Сервер: `POST /auth/invitations`, `DELETE /auth/invitations/:id` (только `ADMIN`), публичные `GET /auth/invitations/:token`, `GET /auth/google/start`, `GET /auth/google/callback`. Модели `invitations` (хеш токена, срок 1 день, статус) и `oauth_states` (TTL 10 минут), поле `users.googleSub`. Проверка ID-токена на `node:crypto` (RS256, `kid`, `iss`, `aud`, `exp`, `nonce`, `email_verified`), без новых зависимостей.
  - Тесты: `test/api/google-signin.test.ts` (Google заменён заглушкой `fetch`, подписи настоящие), строки в `access.test.ts`, `openapi.json` обновлён.
  - Клиент: `/connect/:token` (карточка игрока и «Continue with Google»), `/connect/failed`, `/connected`; все нерабочие ссылки выглядят одинаково.
  - Настройка: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` в `server-nest/.env`; без них маршруты `/auth/google/*` отвечают 503. Живой вход проверить можно только с настоящими ключами: в тестах его нет.
  - После привязки вход по паролю для этой записи закрыт.
