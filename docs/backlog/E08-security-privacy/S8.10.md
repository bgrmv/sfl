# S8.10 — Не отдавать email и персональные данные публичными эндпоинтами

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S0.1](../E00-security-hotfix/S0.1.md)

**DESC:** Как игрок, я хочу, чтобы мой email, имя и фамилия не были видны всем без входа, чтобы нельзя было собрать список адресов.

**ACs:**
- [x] Публичные `GET /players`, `GET /players/:id`, `GET /charts/top-*` не возвращают `email` и фамилию; остаётся только то, что нужно для отображения (никнейм, номер) (D3).
- [x] Полные данные пользователя отдаются только авторизованным и только администратору.
- [x] Клиент не использует удалённые поля или получает их через защищённый эндпоинт; страницы игроков и графики работают.
- [x] Тест: публичный запрос не содержит `email` ни в одном поле.

## Заметки

- Источник: [аудит кода 2026-11-13](../../audits/code-2026-11-13.md), D3. Воспроизведено: публичный `GET /players` содержит `user.email`.
- Общая политика персональных данных и GDPR — [S8.4](S8.4.md); эта история закрывает самый острый случай до неё.

- **Сделано 2026-11-13.** Публичные `GET /players`, `/players/:id`, `/players/captains` отдают у пользователя только `name` и `avatar` (без email, фамилии, возраста и id), графики `/charts/top-*` — только `name`. Для графиков белый список через `$project`: вложенный `$set` в агрегации сливает поля, а не заменяет.
- Полные данные получает `ADMIN` **на тех же маршрутах**: клиент и так шлёт токен, поэтому диалоги редактирования, удаления и карточка игрока работают без правок клиента. Для этого `AuthGuard` на публичных маршрутах необязательно опознаёт вызывающего (битый токен не ошибка, ответ просто урезан). Минус: ответ зависит от токена, поэтому кеш на прокси должен учитывать `Authorization` ([S7.4](../E07-vps-hosting/S7.4.md)).
- Подписи на графиках теперь «ник (Имя)» без фамилии: клиент уже обрабатывает отсутствие фамилии, правок не потребовалось. Если фамилия в подписи нужна, решение за владельцем (S8.4).
- Не проверено: клиент в браузере (окружение не запускает клиентские шаги `pnpm check`, Node 22.16 < 22.22.3).
