# S8.10 — Не отдавать email и персональные данные публичными эндпоинтами

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S0.1](../E00-security-hotfix/S0.1.md)

**DESC:** Как игрок, я хочу, чтобы мой email, имя и фамилия не были видны всем без входа, чтобы нельзя было собрать список адресов.

**ACs:**
- [ ] Публичные `GET /players`, `GET /players/:id`, `GET /charts/top-*` не возвращают `email` и фамилию; остаётся только то, что нужно для отображения (никнейм, номер) (D3).
- [ ] Полные данные пользователя отдаются только авторизованным и только администратору.
- [ ] Клиент не использует удалённые поля или получает их через защищённый эндпоинт; страницы игроков и графики работают.
- [ ] Тест: публичный запрос не содержит `email` ни в одном поле.

## Заметки

- Источник: [аудит кода 2026-11-13](../../audits/code-2026-11-13.md), D3. Воспроизведено: публичный `GET /players` содержит `user.email`.
- Общая политика персональных данных и GDPR — [S8.4](S8.4.md); эта история закрывает самый острый случай до неё.
