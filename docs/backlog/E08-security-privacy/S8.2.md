# S8.2 — Защита входа от перебора

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S0.1](../E00-security-hotfix/S0.1.md)

**DESC:** Как пользователь, я хочу, чтобы мой пароль нельзя было подобрать перебором, чтобы аккаунт был в безопасности.

**ACs:**

- [x] Лимит попыток входа на `POST /rest/auth/sign-in` по IP и по email (`@nestjs/throttler` или аналог). За прокси Caddy учитывается реальный IP клиента.
- [ ] Требования к паролю: минимальная длина и проверка по списку утёкших паролей (например, k-anonymity API Have I Been Pwned).
- [ ] При необходимости добавлена CAPTCHA на форму входа.

## Заметки

- **Лимит попыток сделан в [S8.11](S8.11.md)** (2026-11-15): по IP и по e-mail, настраивается окружением, `429` с `Retry-After`. Первый AC закрыт там.
- **Остаётся:** требования к паролю (длина, проверка по списку утёкших паролей через HIBP: наружу уходят только 5 символов хеша, нужно согласие владельца) и CAPTCHA. CAPTCHA при лимите попыток и небольшой лиге, скорее всего, не нужна: делать только при реальной проблеме. Статус ❌ до решения по двум оставшимся пунктам.
