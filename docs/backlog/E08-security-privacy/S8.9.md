# S8.9 — Авторизация по ролям на сервере и защита от mass assignment

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** M · **Зависит от:** [S2.4](../E02-tests-ci/S2.4.md)

**DESC:** Как владелец лиги, я хочу, чтобы изменять и удалять игроков, матчи и роли мог только администратор, а поля пользователя нельзя было переписать произвольным телом запроса.

**ACs:**
- [ ] Есть декоратор ролей и guard: изменяющие эндпоинты матчей, игроков, команд, ролей и миграций требуют роль `ADMIN`; рядовой `USER` получает 403 (D1). Тест на матрицу «роль × маршрут».
- [ ] `PATCH /players/:id` принимает только белый список полей игрока и пользователя; `roles`, `password`, `email` другого пользователя не меняются (D2). Тест: попытка поменять `roles` → 400 или поле игнорируется.
- [ ] Смена пароля идёт через отдельный эндпоинт с хешированием ([S8.7](S8.7.md)), открытым текстом пароль не сохраняется.
- [ ] `GET /migrations/convert-players-user-to-uuid` перестаёт быть GET: либо `POST` только для `ADMIN`, либо скрипт убирается из API (D4); `eachAsync` ожидается.
- [ ] Матрица прав записана в документации и покрыта тестами ([S2.4](../E02-tests-ci/S2.4.md)).

## Заметки

- Источник: [аудит кода 2026-11-13](../../audits/code-2026-11-13.md), группа D.
- Интерфейсные роли ([S8.1](S8.1.md)) делаются после серверных: клиент только скрывает кнопки, защита должна быть на сервере.
- Роли берутся из токена (`roles` в полезной нагрузке), проверять их на сервере нужно по актуальным данным, если важен немедленный отзыв прав.
