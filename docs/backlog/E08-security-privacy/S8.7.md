# S8.7 — Современное хеширование паролей

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S4.3](../E04-migration-design/S4.3.md), [S2.4](../E02-tests-ci/S2.4.md)

**DESC:** Как пользователь, я хочу, чтобы даже при утечке базы мой пароль нельзя было быстро подобрать, и чтобы для этого мне не пришлось ничего делать.

**ACs:**

- [x] Новые и изменённые пароли хешируются argon2id (или bcrypt, по решению [S4.3](../E04-migration-design/S4.3.md)) с солью.
- [x] При успешном входе с паролем в старом SHA-512 хеш сразу пересчитывается в новый алгоритм.
- [x] У пользователя хранится признак алгоритма хеша. Видно, сколько аккаунтов ещё не переведено.
- [x] Тесты: вход со старым хешем переводит его в новый; вход с новым хешем работает; неверный пароль отклоняется в обоих случаях.
- [x] По истечении срока из [S4.3](../E04-migration-design/S4.3.md) оставшиеся SHA-512 хеши удаляются отдельным скриптом.
- **Сделано 2026-11-18.** Библиотека [`@node-rs/argon2`](https://www.npmjs.com/package/@node-rs/argon2) (предсобранные бинарники, без install-скриптов; `argon2id`, параметры минимума OWASP: 19 МиБ, 2 прохода). Выбрана вместо `argon2`: нативная сборка не нужна. Пакет [password.ts](../../../server-nest/src/shared/utils/password.ts), вход — [auth.service.ts](../../../server-nest/src/entities/auth/auth.service.ts).
- **Признак алгоритма:** поле `passwordAlgorithm` (`sha512` | `argon2id`), у старых документов поля нет, это `sha512`. Сколько аккаунтов не переведено: `POST /migrations/revoke-legacy-passwords` без `apply` (пробный прогон) возвращает `total`, `legacy`.
- **Удаление остатков (AC 5).** Тот же маршрут с `{ "apply": true }`: каждому аккаунту без argon2id ставится случайный пароль и завершаются сессии; аккаунт и игрок остаются, доступ возвращает ссылка администратора ([S10.48](../E10-product-features/S10.48.md)). Запуск в срок — отдельная история [S8.15](S8.15.md) (P4): через 12 месяцев после выхода этой истории на прод: раньше пользователь без входа теряет доступ зря. **Дата запуска зависит от выкатки на прод (P4), поставьте напоминание после неё.**
- Вход с несуществующим email тратит столько же времени, как неверный пароль (хеш-заглушка), иначе argon2 сделал бы перебор email заметным по времени ответа.
- Перевод хеша при входе не меняет `tokenVersion`: сессии остаются. Запись условна по старому хешу, смена пароля между проверкой и записью не перезаписывается.
- Старое имя `hash()` заменено на `sha512Legacy()`; тесты по-прежнему сидируют старые хеши через него.
