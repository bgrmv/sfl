# S8.8 — Локальная проверка секретов и уязвимых зависимостей

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S2.8](../E02-tests-ci/S2.8.md)

**DESC:** Как разработчик, я хочу проверять репозиторий на секреты и уязвимые зависимости локально, не дожидаясь CI, чтобы история с паролями в `_backups` и passphrase не повторилась.

**ACs:**
- [x] В `pnpm check` ([S2.8](../E02-tests-ci/S2.8.md)) добавлены два шага: `pnpm audit --audit-level high` в обоих пакетах и сканер секретов (например, gitleaks) по рабочему дереву и по истории git.
- [x] Сканер ставится в dev-контейнер без ручных шагов (версия зафиксирована). Исключения (тестовые значения вроде `dev-admin`) описаны в конфиге сканера с причиной.
- [x] Первый прогон по истории выполнен. Находки записаны в отчёт `docs/audits/secrets-YYYY-MM-DD.md` без самих секретов (только файл, коммит, тип). Находки, которые нужно ротировать, заведены историями или записаны в [S0.5](../E00-security-hotfix/S0.5.md).
- [x] Найденные уязвимости высокой серьёзности либо исправлены обновлением зависимости, либо записаны с причиной «принимаем риск».
