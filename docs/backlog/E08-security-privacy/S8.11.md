# S8.11 — Защита от перебора, заголовки и Swagger

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S2.4](../E02-tests-ci/S2.4.md)

**DESC:** Как владелец, я хочу, чтобы вход нельзя было перебирать, а сервер не раскрывал лишнего о себе, чтобы публичный API был устойчив к простым атакам.

**ACs:**

- [x] Rate limit на `POST /auth/sign-in` (например, 5 попыток в минуту с одного IP и email) и мягкий общий лимит на остальной API. Превышение даёт `429`. Лимиты настраиваются окружением (G1).
- [x] Подключён `helmet`: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`; `X-Powered-By` выключен. HSTS и CSP — на уровне прокси ([S7.4](../E07-vps-hosting/S7.4.md)), решение записано в `## Заметки` (H1).
- [x] Swagger UI доступен только вне production (H2).
- [x] API-тесты в `server-nest/test/api/`: 6-я неверная попытка входа даёт `429`, ответ не содержит `X-Powered-By`, в prod-режиме `GET /rest` даёт 404.
- [x] Лимит не ломает локальные тесты и dev-вход: тесты используют отдельную конфигурацию.

## Заметки

- Источник: [аудит безопасности 2026-11-13](../../audits/security-2026-11-13.md), находки G1, H1, H2. Перебор подтверждён: 30 попыток за 111 мс, все 401.
- Связана с [S8.7](S8.7.md): пока хеши SHA-512 без соли, лимит — единственная защита от быстрого перебора.
- **Сделано 2026-11-15.** `@nestjs/throttler` 6 (три лимитера: `api` общий, `sign-in-ip` и `sign-in-email` строгие, e-mail без учёта регистра) и `helmet` 8; обе зависимости названы в этой истории и в [S8.2](S8.2.md). Лимиты задаются окружением: `SIGN_IN_LIMIT` (5), `SIGN_IN_WINDOW_SEC` (60), `API_LIMIT` (300), `API_WINDOW_SEC` (60). Ответ `429` приходит в формате [ADR 0011](../../adr/0011-result-response-format.md) (`TOO_MANY_REQUESTS`) со стандартным `Retry-After`. Общая настройка приложения вынесена в `src/app.setup.ts` и используется и в `main.ts`, и в API-тестах, чтобы они не расходились. Тесты: `server-nest/test/api/hardening.test.ts`.
- **H1, заголовки.** `helmet` без HSTS и CSP: их ставит прокси ([S7.4](../E07-vps-hosting/S7.4.md)). `Cross-Origin-Resource-Policy: cross-origin`, потому что клиент на другом origin.
- **H2, Swagger** включается только вне production.
- **Ограничения.** Счётчики хранятся в памяти процесса: с одним экземпляром приложения (наш случай) этого достаточно, при нескольких нужен общий storage (Redis). За прокси в production включён `trust proxy` на один переход: когда появится Caddy ([S7.3](../E07-vps-hosting/S7.3.md)), проверить, что в лимитер попадает реальный IP клиента.
- **На полях.** Если приложение будет в нескольких экземплярах, счётчики лимита перенести в общий storage (Redis, `@nest-lab/throttler-storage-redis`). Лимит не заменяет медленный хеш: [S8.7](S8.7.md).
