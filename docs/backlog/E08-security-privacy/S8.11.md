# S8.11 — Защита от перебора, заголовки и Swagger

**Эпик:** 8 — Безопасность и персональные данные · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** [S2.4](../E02-tests-ci/S2.4.md)

**DESC:** Как владелец, я хочу, чтобы вход нельзя было перебирать, а сервер не раскрывал лишнего о себе, чтобы публичный API был устойчив к простым атакам.

**ACs:**
- [ ] Rate limit на `POST /auth/sign-in` (например, 5 попыток в минуту с одного IP и email) и мягкий общий лимит на остальной API. Превышение даёт `429`. Лимиты настраиваются окружением (G1).
- [ ] Подключён `helmet`: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`; `X-Powered-By` выключен. HSTS и CSP — на уровне прокси ([S7.4](../E07-vps-hosting/S7.4.md)), решение записано в `## Заметки` (H1).
- [ ] Swagger UI доступен только вне production (H2).
- [ ] API-тесты в `server-nest/test/api/`: 6-я неверная попытка входа даёт `429`, ответ не содержит `X-Powered-By`, в prod-режиме `GET /rest` даёт 404.
- [ ] Лимит не ломает локальные тесты и dev-вход: тесты используют отдельную конфигурацию.

## Заметки

- Источник: [аудит безопасности 2026-11-13](../../audits/security-2026-11-13.md), находки G1, H1, H2. Перебор подтверждён: 30 попыток за 111 мс, все 401.
- Связана с [S8.7](S8.7.md): пока хеши SHA-512 без соли, лимит — единственная защита от быстрого перебора.
