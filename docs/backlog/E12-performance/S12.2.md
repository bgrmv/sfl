# S12.2 — Аудит запросов и индексов MongoDB

**Эпик:** 12 — Производительность и оптимизация · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S11.8](../E11-dx-docs/S11.8.md)

**DESC:** Как администратор лиги, я хочу знать, какие запросы к базе медленные или лишние, чтобы список матчей, пересчёт статистики и графики не замедлялись с ростом данных.

**ACs:**
- [ ] Для каждого эндпоинта `server-nest` записаны выполняемые запросы Mongo, их число на запрос API (поиск N+1) и время на локальной копии прода.
- [ ] Для основных запросов снят `explain("executionStats")`: сканирование коллекции или индекс, число просмотренных и возвращённых документов.
- [ ] Проверено, какие индексы объявлены в схемах и какие есть в базе. В локальной копии у всех коллекций только индекс `_id`; нужно выяснить, это потеря при дампе или в схемах индексов нет, в том числе уникальных (`users.email`).
- [ ] Разобраны пересчёты метаданных игроков при создании, изменении и удалении матча (`runMetadataFlow`, `recalculatePlayersSeasonAndCareerMetadata`): сколько документов читают и пишут, нет ли пересчёта всего сезона ради одного матча. Отдельно записано, что после удаления матча в `players.metadata.bySeason` остаётся пустая запись сезона.
- [ ] Отчёт `docs/audits/perf-db-YYYY-MM-DD.md`. Агент не правит код и не создаёт индексы в базе.
- [ ] По каждой находке заведена история ([S12.4](S12.4.md) или другая) либо записано «не делаем» с причиной.

## Заметки

- Измерения только на локальной копии. Прод-Atlas и боевые адреса не трогаем.
