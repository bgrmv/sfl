# S10.18 — Статус матча «Пропущен»

**Эпик:** 10 — Продуктовые фичи · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** S · **Зависит от:** —

**DESC:** Как администратор лиги, я хочу отметить неделю, когда матч не состоялся, чтобы в ленте не было дыры и рейтинги не страдали.

**ACs:**

- [x] В `@sfl/schemas` `EnumGameStatus` дополнен значением «Пропущен»; формы данных API общие для клиента и сервера ([ADR 0010](../../adr/0010-zod-mini-in-shared-schemas.md)).
- [x] Матч со статусом «Пропущен» не требует составов и статистики, не учитывается ни в одном рейтинге и расчёте метаданных; правило записано в [GLOSSARY.md](../../../GLOSSARY.md) (сделано).
- [x] Расчёт статистики пропускает такие матчи; тест на это и на `it.fails`-кейсы расчёта не ломается.
- [x] Клиент: администратор создаёт «Пропущен» в форме матча, в ленте неделя отмечена («Skipped»), блок «Ближайший матч» не ломается.
- [x] `pnpm check` проходит.

## Заметки

- Источник: решение владельца 2026-11-13: матч состоится в любую погоду, с 1980 года ни одна неделя не пропущена; статус введён на всякий случай.
- **Сделано 2026-11-17:** `EnumGameStatus.Skipped = 'skipped'`; `gameRuleViolations` для него возвращает пусто (форма клиента и сервер используют одно правило). Сервер (`GamesService.runMetadataFlow`) для «Пропущен» не считает метаданные матча и снимает поле `metadata`; расчёт игроков и так берёт только опубликованные, поэтому вклад ранее опубликованного матча вычитается (тест в `statistics.incremental.test.ts`). Клиент: пункт Skipped в поле статуса формы (статусы New и Skipped меняются вручную, Draft и Published только чтением), клетка ленты `skipped` (зачёркнута, подпись «skip», легенда), карточка «Skipped: no game this week» в списке, фильтр и значок на доске игр. «Ближайший матч» не затрагивается: он строится по плейсхолдерам суббот.
- Вид формы и ленты в браузере не смотрен.
