# S10.52 — Админка «Releases»: заметки релиза как на GitHub

**Эпик:** 10 — Продуктовые фичи · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P3 · **Размер:** M · **Зависит от:** [S10.51](S10.51.md), [S10.35](S10.35.md)

**DESC:** Как владелец и разработчик, я хочу видеть в админке список релизов с датой, что сделано и починено, коммитами, pull request и миграциями, как на GitHub, и публиковать из него короткую версию на публичную страницу.

**ACs:**

- [ ] Раздел «Releases» в меню админки: список (вкладки «All», «Published», «Drafts», «Pre-releases»), у релиза тег (`v2026.11.3`), метки «Latest» и «Deployed», дата и время, автор, ветка и коммит, число коммитов с прошлого релиза, ссылка «Compare предыдущий…текущий».
- [ ] Тело релиза «What’s Changed»: группы Features, Fixes, Tests, docs and chores; строка: тип и область коммита, текст, ссылка на историю бэклога, короткий хеш коммита, номер pull request, автор; «Full Changelog».
- [ ] Блок эксплуатации: деплой (среда, время, длительность, проверка здоровья), миграции базы (сколько применено, сколько документов затронуто), несовместимые изменения (нет или перечень), безопасен ли откат; вложения (архив сборки, отчёт миграции).
- [ ] Редактор нового релиза: тег, целевая ветка, предыдущий тег, заголовок; «Generate release notes» собирает заметки из коммитов по соглашению `feat:` `fix:` `docs:` `test:` `chore:` (AGENT.md) и идентификаторов историй в сообщениях, правки автора сохраняются при повторной генерации; режимы «Write» и «Preview».
- [ ] Список коммитов с прошлого релиза с видом, автором и временем; перед публикацией чек-лист (зелёный `pnpm check`, нет несовместимых изменений, миграция обратима и прогнана на копии, сегодняшний бэкап).
- [ ] Публикация создаёт тег на выбранной ветке и необратима (ошибку исправляет следующий релиз); «Discard draft» красным контуром; «Set as the latest», «Pre-release».
- [ ] Связь с публичной страницей ([S10.51](S10.51.md)): переключатель «Show on the public Release notes page» и отдельное короткое резюме для посетителей; технические подробности публично не показываются.
- [ ] Опция «Mark these stories as done»: найденные истории с полностью отмеченными AC переводятся из ❌ в ✅ в индексе бэклога; сохраняется ссылка на релиз.
- [ ] Источник данных: Markdown в репозитории (`docs/releases/ГГГГ.ММ.N.md`) и журнал git; доступ только `ADMIN` (чтение у `MODERATOR`); тема только тёмная.

## Заметки

- Макет: холст «Табло», секция «4г-2» (список, новый релиз, телефон).
- Решение владельца 2026-11-15: публичная страница нравится, в админке нужна вторая, технически подробная, как release notes на GitHub.
- Деплой и откат относятся к P4 ([S7.x](../E07-vps-hosting/)); до их появления блок «Deploy» ведётся вручную.
