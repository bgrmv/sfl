# S10.21 — Дашборд администратора

**Эпик:** 10 — Продуктовые фичи · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P3 · **Размер:** L · **Зависит от:** [S10.19](S10.19.md), [S10.22](S10.22.md), [S8.1](../E08-security-privacy/S8.1.md)

**DESC:** Как администратор лиги, я хочу одно место для работы с лигой: создать матч, провести драфт, ввести статистику, сменить статус и проверить комментарии, чтобы публичный сайт оставался только для чтения.

**ACs:**

- [ ] Дашборд лежит в отдельной части клиента ([S10.19](S10.19.md)) и закрыт guard по роли `ADMIN` ([S3.10](../E03-architecture/S3.10.md)); публичные страницы не содержат действий записи.
- [ ] Главный экран: ближайшая суббота, матчи, ждущие действия (новый без статистики, черновик, ждущие публикации), очередь комментариев на проверку, быстрые действия «Создать матч» и «Опубликовать».
- [ ] Создание матча идёт семью шагами на отдельных страницах: игра (дата, номер, сезон), капитаны, драфт, статистика (итоги по игрокам), порядок голов (необязательный, [S10.27](S10.27.md)), проверка, публикация. На каждом шаге виден список шагов, назад и вперёд; черновик сохраняется на любом шаге. Ошибки правил ([S3.13](../E03-architecture/S3.13.md): один капитан, позиция) показываются рядом с полем и в проверке, публикацию блокируют.
- [ ] Сводка матча закреплена сверху на всех шагах: число игроков, голы, голы головой и передачи каждой команды, итоговый счёт и оценка шанса на победу ([S10.25](S10.25.md)); значки из [S10.26](S10.26.md).
- [ ] Капитаны выбираются первым шагом и выделены: жёлтая карточка «Captain», пометка в списке драфта, в составах и на карте расстановки; капитан делает первый пик, команда первого капитана — «1-й драфт».
- [ ] Страница статистики: у каждого игрока счётчики гола, гола головой, пенальти, автогола и передачи, переключатель MVP, позиция и трансфер; значки в заголовках; правка не требует прокрутки в сторону на 360 px.
- [ ] Смена статуса матча: новый → черновик → опубликован и «пропущен» ([S10.18](S10.18.md)); при публикации показано, какие итоги игроков изменятся; ответ сервера принимается без полной перезагрузки ([S3.22](S3.22.md)).
- [ ] Модерация комментариев: очередь, одобрить, отклонить, удалить; для каждого видно матч, автора и дату.
- [ ] Права проверяются на сервере, новые маршруты закрыты строкой в `test/api/access.test.ts`; действия администратора записываются (кто, что, когда).
- [ ] Светлая и тёмная тема, 360 и 1280 px; действия не сбивают ввод при ошибке.
