# S5.2 — Таблицы, enum-ы, ограничения

**Эпик:** 5 — Бэкенд на Supabase · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P2 · **Размер:** M · **Зависит от:** [S4.2](../E04-migration-design/S4.2.md), [S5.1](../E05-supabase-backend/S5.1.md)

**DESC:** Как разработчик, я хочу схему Postgres по утверждённому дизайну, чтобы база сама не допускала некорректных данных.

**ACs:**
- [ ] Созданы таблицы и enum-ы из [S4.2](../E04-migration-design/S4.2.md) одной миграцией.
- [ ] Внешние ключи, `NOT NULL`, `UNIQUE` и `CHECK` (например, неотрицательные голы и пасы, ровно две команды на матч).
- [ ] Индексы на частые запросы: матчи по сезону и номеру, статистика по игроку и сезону.
- [ ] Колонки `created_at`, `updated_at` с триггером обновления.
