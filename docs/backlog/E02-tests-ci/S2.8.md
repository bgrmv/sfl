# S2.8 — Единая локальная команда проверки

**Эпик:** 2 — Тесты и CI · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** S · **Зависит от:** [S1.2](../E01-dependency-upgrades/S1.2.md)

**DESC:** Как разработчик (или ИИ-агент), я хочу запускать все проверки одной командой в dev-контейнере, чтобы каждое обновление, аудит и рефакторинг проверялись одинаково без CI.

**ACs:**
- [ ] В корне есть команда `pnpm check` (или `make check`). Для каждого пакета она запускает: `lint` без `--fix`, проверку типов (`tsc --noEmit`), тесты и production-сборку. Каждый шаг выводится отдельной строкой «шаг: ок/упал».
- [ ] Команда падает на первой ошибке и возвращает ненулевой код. Флаг `--all` прогоняет все шаги и печатает сводку.
- [ ] Шаги, которые сейчас упасть не могут по известным причинам (линт сервера из-за [S1.6](../E01-dependency-upgrades/S1.6.md), клиентские тесты из-за [S2.5](S2.5.md)), перечислены в одном месте с причиной и ссылкой. Их можно временно пропускать флагом `--skip`, а не молча отключать.
- [ ] Команда не меняет файлы (линт без `--fix`) и не обращается к сети и к базе.
- [ ] README и AGENT.md ([S11.5](../E11-dx-docs/S11.5.md)) описывают команду. Агент обязан запускать её перед тем, как предлагать коммит.
- [ ] Проверка уложена в 3 минуты на чистом контейнере.

## Заметки

- Эта история заменяет CI для локальной работы. Когда дойдёт до [S2.1](S2.1.md), CI просто запускает ту же команду, а не дублирует список шагов.
- Хуки pre-commit ([S11.7](../E11-dx-docs/S11.7.md)) гоняют лёгкую часть (lint-staged), полный `check` остаётся ручным.
