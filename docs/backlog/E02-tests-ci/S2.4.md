**DESC:** Как разработчик, я хочу интеграционные тесты API с тестовой базой, чтобы проверять права доступа и основные операции при каждом изменении.

**ACs:**
- [x] Тесты на `supertest` и `mongodb-memory-server`. Внешняя база не нужна.
- [x] Матрица доступа: каждый изменяющий маршрут без токена — `401`, с токеном — успех.
- [x] CRUD-сценарии для матча и игрока, включая невалидное тело (`400`).
- [x] Шаблонный `test/app.e2e-spec.ts` заменён рабочими тестами.

## Заметки

- AC «Тесты запускаются в CI на каждый PR» перенесён в [S2.1](S2.1.md) по решению владельца (2026-11-13): CI относится к P4. Локально тесты входят в `pnpm check` (шаг `server:test`).
- Тесты лежат в `server-nest/test/api/` (`access`, `games`, `players`), общий код — в `test/helpers/`. Приложение — настоящий `AppModule` на `mongodb-memory-server`, вход через настоящий `POST /auth/sign-in`. При первом запуске скачивается бинарник mongod (~100 МБ, кэш в `~/.cache/mongodb-binaries`).
- Матрица содержит тест полноты: новый закрытый маршрут без строки в матрице роняет тесты.
- Известные дефекты из [отчёта S11.9](../../audits/code-2026-11-13.md) записаны как `it.fails` (проходят, пока дефект есть, краснеют после исправления; тогда `.fails` убрать): дубль матча и удаление несуществующего (500, S3.12), матч без капитана (500, остаётся в базе, S3.12), пустые metadata в ответе создания (S3.11), `/players/captains` (500, S3.12), `POST /players` с ошибкой (201, S3.12), несуществующий игрок (500, S3.12), mass assignment `PATCH /players/:id` (S8.9), email в публичном `GET /players` (S8.10).
- Роли на сервере ещё не проверяются (S8.9): матрица проверяет только наличие токена, проверок «рядовой игрок не может» пока нет.
