# S2.2 — Golden-master тесты расчёта статистики

**Эпик:** 2 — Тесты и CI · **Статус:** в [индексе бэклога](../README.md)

**Приоритет:** P1 · **Размер:** L · **Зависит от:** [S11.2](../E11-dx-docs/S11.2.md)

**DESC:** Как разработчик, я хочу тесты, которые сравнивают расчёт статистики с реальными прод-значениями, чтобы при рефакторинге, обновлениях и переездах цифры игроков не изменились незаметно.

**ACs:**

- [x] Из прода снят анонимизированный снапшот: все матчи и сохранённые `metadata` игроков и матчей.
- [x] Тест берёт матчи снапшота, считает метаданные текущим кодом и сравнивает с сохранёнными `byGame`, `bySeason`, `byCareer` для каждого игрока, включая обе рейтинговые системы (ancient и positional).
- [x] Расхождения выводятся по игроку, сезону и полю. Известные расхождения (например, из-за старых ошибок в данных) зафиксированы в файле исключений с объяснением.
- [x] Тест запускается локально (`pnpm test` сервера, пропускается без набора), снапшот хранится вне репозитория (`_dumps/`, в `.gitignore`). Запуск в CI — [S2.1](S2.1.md) (P4), там же решить, класть ли обезличенный набор в репозиторий.

## Заметки

- **Сделано 2026-11-15.** Тест [server-nest/test/golden/golden-master.test.ts](../../../server-nest/test/golden/golden-master.test.ts): обезличенный набор ([S11.2](../E11-dx-docs/S11.2.md)) грузится в in-memory MongoDB, метаданные каждого матча и игрока считаются заново настоящим кодом (`GamesService` и `PlayersService`, без правок кода), результат сравнивается дважды: с метаданными из дампа (отчёт `golden-report.json` по матчу, игроку, сезону и полю, не падение) и с базовой линией текущего кода `golden-baseline.json` (создаётся при первом запуске; рефакторинг [S3.1](../E03-architecture/S3.1.md), [S3.3](../E03-architecture/S3.3.md), [S3.5](../E03-architecture/S3.5.md) её менять не должен). Известные расхождения зафиксированы базовой линией; осознанное изменение правил — удалить базовую линию и создать заново.
- **Что показал первый прогон** (16 матчей, 232 игрока): метаданные в дампе посчитаны старым кодом, и после исправлений [S3.11](../E03-architecture/S3.11.md) отличаются у всех 16 матчей (`mvpByGoalsIds`, капитаны победы и поражения) и у 54 игроков (чаще всего `totalLostGames`, `positionalRatingSystem`, `ancientRatingSystem.lastResult`, серии и `totalMvpByGoals`). Это ожидаемый эффект ошибок A1 и A3 из [аудита](../../audits/code-2026-11-13.md); пересчёт прода — [S3.14](../E03-architecture/S3.14.md).
- **Находка: у всех 16 матчей прода статус `new`**, хотя в них есть статистика и метаданные. По правилу «в итоги идут только опубликованные» ([GLOSSARY](../../../GLOSSARY.md)) после выкладки исправлений все сезонные и карьерные итоги обнулятся, пока статусы не поправят. Тест считает матчи со статистикой опубликованными; миграция статусов — в [S3.14](../E03-architecture/S3.14.md).
- Побочное: Mongoose предупреждает, что опция `new` у `findOneAndUpdate` устарела (нужно `returnDocument: 'after'`), код `games.service.ts` её ещё использует.
