## 1. Ответ API как `Result<T, E>` {#1}

**Суть.** Каждый ответ — `{ ok: true, data }` или `{ ok: false, error: { status, code, message, issues? } }`, как `Result<T, E>` в Rust. HTTP-статус остаётся настоящим (2xx или 4xx/5xx), `code` — стабильная строка (`NOT_FOUND`, `VALIDATION_FAILED`). В коде тип — `Ok`/`Err` с `map`, `mapErr`, `andThen`, `match`, `unwrapOr`; JSON по сети превращает обратно `fromSerialized`.

**Польза.**

- Клиент и сервер говорят на одном типе, у ошибок один формат вместо трёх.
- Дискриминатор `ok` сужает типы без приведений.
- Ошибка — значение: `toResult()` на клиенте делает поток, который не умирает от 404 (в RxJS ошибка без `catchError` завершает внешний поток).
- Клиент ветвится по `code`, а не по тексту сообщения.

**Как перенести.**

1. Опишите `Result`, `ApiError`, `fromSerialized`, `fromPromise` в общем пакете ([result.ts](../packages/schemas/src/result.ts), [api-response.ts](../packages/schemas/src/api-response.ts)).
2. На сервере: глобальный перехватчик оборачивает возвращаемое значение в `ok(...)`, глобальный фильтр превращает исключение в `err(...)` и ставит статус ([response.interceptor.ts](../server-nest/src/shared/interceptors/response.interceptor.ts), [all-exceptions.filter.ts](../server-nest/src/shared/filters/all-exceptions.filter.ts)). Контроллеры возвращают обычные значения и не трогают `@Res()`.
3. На клиенте: один сервис HTTP снимает обёртку, оператор `toResult()` ([to-result.ts](../client/src/shared/api/to-result.ts)) нужен экранам, которые реагируют на ошибку.
4. Тест: тело успеха, тело ошибки, одинаковая форма всех ошибок ([players.test.ts](../server-nest/test/api/players.test.ts)).

**Оговорки.**

- Внутри сервера остаются исключения Nest: так идёт идиома фреймворка, а монада живёт на границе. Переписывать сервисы на `Result` не стали.
- В сигналах и сторах лучше хранить простой JSON-объект (`toJSON()`), а не экземпляры классов: сравнение по ссылке и SSR-сериализация проще. В SFL `toResult()` пока отдаёт класс; для сигналов см. [п. 14](#14).
- Решение и отклонённые варианты: [ADR 0011](adr/0011-result-response-format.md).

## 2. Права «закрыто по умолчанию» {#2}

**Суть.** Два глобальных guard'а: токен обязателен, роль `ADMIN` обязательна. Исключения явные: `@Public()` и `@Roles(...)`.

**Польза.** Разработчик, забывший декоратор, получает 403, а не открытый маршрут. Аудит безопасности нашёл, что роли раньше не проверялись нигде: ошибка «забыл закрыть» перестала быть возможной.

**Как перенести.** Глобальные `APP_GUARD` (auth, затем roles), декораторы-исключения, матрица «роль × маршрут» в тесте. Важная часть — тест полноты: он падает, если у маршрута нет строки в матрице ([access.test.ts](../server-nest/test/api/access.test.ts)).

**Оговорки.** Роли берутся из токена и действуют до 15 минут после смены; проверка по базе — история [S8.12](backlog/E08-security-privacy/S8.12.md). [ADR 0006](adr/0006-server-roles-closed-by-default.md).

## 3. Схема zod — один источник формы данных {#3}

**Суть.** Форма данных API объявлена один раз как схема в общем пакете `@sfl/schemas`; типы выводятся `z.infer`, клиент и сервер проверяют теми же схемами. В клиентском пакете используется `zod/mini`, у сервера для собственных DTO — обычный `zod`.

**Польза.** Меньше дублирования `interface`, правила (например, «в команде один капитан») написаны один раз ([`gameRuleViolations`](../packages/schemas/src/schemas.ts)). `zod/mini` вместо классического `zod` сократил клиентский бандл примерно на 84 кБ gzip (измерено, [ADR 0010](adr/0010-zod-mini-in-shared-schemas.md)).

**Как перенести.** Пакет в pnpm workspace, сборка `tsc` в ESM, подключение `workspace:*`; `pnpm check` сначала собирает пакеты. У клиента и сервера отдельные lock-файлы, если `node_modules` живут в томах контейнера ([ADR 0009](adr/0009-pnpm-workspace-separate-lockfiles.md)).

**Оговорки.** Мигрировано не всё: часть типов клиента и сервера дублируется, чистка — [S3.19](backlog/E03-architecture/S3.19.md) (там же OpenAPI из схем).

## 4. Проверка контракта на границе {#4}

**Суть.** Ответ API проходит через оператор `checkedResponse(schema, source)`: валидные данные выходят разобранными (значения по умолчанию применены), невалидные логируются с путём и сообщением, но идут дальше как есть. Флаг `STRICT` превращает расхождение в ошибку ([checked-response.ts](../client/src/shared/api/checked-response.ts)).

**Польза.** Старые данные в базе (поля, которых не было раньше) не ломают экран, но расхождение видно в консоли. Когда реальные данные проверены, включаем `STRICT`.

**Как перенести.** Оператор в `shared/api`, схема из общего пакета, вызов в сервисе на каждом чтении.

## 5. Одна команда проверки {#5}

**Суть.** `pnpm check` из корня: сборка пакетов, линт без `--fix`, типы, тесты, prod-сборка, аудит зависимостей, gitleaks по дереву и истории. Падает на первой ошибке; `--all` даёт сводку. Известные падения не прячутся, а лежат в константе `KNOWN` с причиной ([scripts/check.mjs](../scripts/check.mjs)).

**Польза.** «Готово» значит одно и то же для человека и для агента; до CI (он отложен) именно эта команда — ворота качества.

**Как перенести.** Один скрипт на Node без зависимостей, шаги как массив, вывод «ок (N с)»; pre-commit хук проверяет только изменённое (husky + lint-staged + gitleaks), полный прогон остаётся за командой.

## 6. Бэклог как файлы, индекс — единственный статус {#6}

**Суть.** Одна история — один файл `S<эпик>.<номер>.md` с DESC и ACs-чекбоксами; статус (✅, ❌, ⛔) хранится только в таблице [docs/backlog/README.md](backlog/README.md). Правила выбора следующей истории записаны в [AGENT.md](../AGENT.md): приоритет, зависимости ✅, меньший номер.

**Польза.** Агент (и человек) сам находит следующую задачу и не спорит о приоритетах. Статусы нельзя «забыть обновить в двух местах». Отменённые истории не удаляются: на них ссылаются зависимости.

**Как перенести.** Шаблон истории, таблица со столбцами «приоритет, размер, зависит от», раздел «Заметки» для невыполнимых ACs. Если AC невозможен — не ставить галочку, дописать причину, оставить ❌.

## 7. GLOSSARY и ADR как источник истины {#7}

**Суть.** Язык предметной области и правила расчёта лежат в [GLOSSARY.md](../GLOSSARY.md) с пометкой «Avoid» для путаных слов; меняете правило — сначала правите там. Каждое значимое решение — короткий ADR с разделами «Рассмотрено» и «Последствия» ([docs/adr/](adr/README.md)).

**Польза.** Спорный расчёт (вес гола головой ×2) нашли как расхождение кода с записью; тесты берут ожидания из глоссария. Причины решений не теряются.

**Как перенести.** Создать `GLOSSARY.md` на первом же обсуждении терминов, ADR заводить, когда выбираете между вариантами и отвергаете один из них.

## 8. Известные дефекты как `it.fails` {#8}

**Суть.** Известный баг записывается тестом с `it.fails` и ссылкой на историю. Когда баг починили, тест начинает «падать» (потому что `.fails` ждёт падения), и вы убираете `.fails`.

**Польза.** Дефект виден в наборе тестов, не теряется в заметках и сам сообщает об исправлении.

## 9. Аудит агентом: только чтение {#9}

**Суть.** Агент-аудитор не правит исходники: он пишет отчёт в `docs/audits/` по общему формату (серьёзность, карта доменных областей), а находки становятся историями бэклога. Правила — skill `audit-report` ([docs/skills.md](skills.md)).

**Польза.** Аудит не смешивается с правками, результат проверяем и разбираем, а не «починено где-то в диффе». Сторонние skills читаются целиком до установки, источник и версия фиксируются.

## 10. Dev-container с синтетическими данными {#10}

**Суть.** Образ с закреплённым Node (проверка контрольной суммы), MongoDB 7, seed на синтетических данных, скрипты `db-dump` и `db-restore` для копий прода (в `_dumps/`, вне git). Скрипт post-create падает с подсказкой, если Node старый.

**Польза.** Новый человек запускает проект без установки Node и MongoDB; реальные данные и хеши паролей не попадают в репозиторий. Подробности — [docs/development.md](development.md).

## 11. FSD + CQRS в TypeScript {#11}

**Суть.**

- **FSD (Feature-Sliced Design)** на клиенте: слои `app → pages → widgets → features → entities → shared`, импорт только вниз, срезы общаются через публичный `index.ts`. Состояние — `@ngrx/signals`.
- **CQRS** на структуре и именах, без шины: в сторах методы-запросы (`load*`, `computed`) и методы-команды (`create*`, `update*`, `delete*`) не смешиваются; на сервере цель — `commands/` и `queries/` внутри модуля сущности, авторизация и валидация (zod) до обработчика. Расчёт статистики — запросы, запись матчей и игроков — команды. Одна БД, без event sourcing.

**Польза.** FSD отвечает на вопрос «куда положить файл» и запрещает циклы между слоями. Лёгкий CQRS даёт читаемый код и повод тестировать запросы отдельно от записи, не платя за шину и две модели данных.

**Как перенести.** Описать слои и правила импорта в PROJECT.md, проверять границы линтером (в SFL это [S3.8](backlog/E03-architecture/S3.8.md)), а CQRS начать с именования и структуры файлов; библиотеку `@nestjs/cqrs` добавлять только когда понадобится шина.

**Оговорки.** Честно: сейчас клиент приведён к FSD не полностью (аудит [fsd-client-2026-11-13.md](audits/fsd-client-2026-11-13.md), история [S3.17](backlog/E03-architecture/S3.17.md)), линтер границ не включён, а CQRS на сервере описан как цель, не как код. Приём ценен именно тем, что договорённость записана раньше, чем код приведён в соответствие.

## 12. Стандарты раньше изобретений {#12}

**Суть.** Правило в [AGENT.md](../AGENT.md): решаем по лучшим практикам и стандартам (официальные руководства, RFC, OpenAPI, OWASP, WCAG). Отступили от стандарта — причину в ADR.

**Польза.** Меньше собственных форматов (ошибка API близка к RFC 9457, а не придумана с нуля), проще объяснять новичку и инструментам.

## 13. Чистка мёртвого кода: knip и ручная проверка {#13}

**Суть.** `knip` находит неиспользуемые файлы, экспорты, зависимости, но даёт ложные срабатывания: скрипты, которые запускают из CLI, барельные `index.ts` (публичный API среза FSD), инструменты, которыми пользуется только `lint-staged`, builder из `angular.json`. Каждую находку проверяем поиском по импортам и селекторам. В SFL так удалили 7 файлов и 8 зависимостей; страницы, чья судьба ещё не решена, оставили ([S11.4](backlog/E11-dx-docs/S11.4.md)).

**Польза.** Чистка без поломок. После удаления зависимостей обязательно `pnpm check` и запуск сервера: инструменты CLI могут держаться на неявных пакетах.

## 15. Лимиты запросов: именованные лимитеры и общая настройка приложения {#15}

**Суть.** В `@nestjs/throttler` один лимитер на правило: `api` (мягкий, на всё), `sign-in-ip` и `sign-in-email` (строгие, только на вход, `skipIf` отсекает остальные маршруты). Ключ e-mail приводится к нижнему регистру. Заголовок `Retry-After` ставит наш guard (стандартный, а не `Retry-After-<имя>`). Настройка приложения (префикс, helmet, cookies, Swagger только вне production) лежит в одной функции `configureApp`, которую вызывают и `main.ts`, и тестовое приложение ([app.setup.ts](../server-nest/src/app.setup.ts)).

**Польза.** Один и тот же код защищает прод и проверяется в тестах: тест не может «зелёно» проходить на конфигурации, которой нет в `main.ts`. Лимит по e-mail ловит подбор одного аккаунта с разных адресов.

**Как перенести.** Лимиты из окружения (в тестах слабые, в тесте лимита сильные), `trust proxy` в production за прокси, тест с `X-Forwarded-For` для разных адресов.

**Оговорки.** Счётчики в памяти (один экземпляр); за прокси нужно проверить реальный IP ([S7.3](backlog/E07-vps-hosting/S7.3.md)). Подробности и результат — [S8.11](backlog/E08-security-privacy/S8.11.md).

## 16. Отзыв сессий без списка отозванных: версия токена {#16}

**Суть.** У пользователя счётчик `tokenVersion`; он лежит в каждом токене как `tv`. Выход и смена пароля увеличивают счётчик, и все refresh-токены с прежним `tv` перестают работать. Access-токен короткий (15 минут) и проверяется без базы. Refresh проверяется с базой, и роли тоже читаются оттуда, поэтому смена роли действует сразу ([auth.service.ts](../server-nest/src/entities/auth/auth.service.ts)). Токены различаются по `aud` (`sfl-access` и `sfl-refresh`), у всех один `iss`, а проверка принимает только `HS512`. Секреты короче 32 символов или одинаковые не дают приложению стартовать.

**Польза.** Настоящий выход и отзыв на всех устройствах без отдельной таблицы чёрного списка; украденная cookie не живёт после смены пароля. Токен не раскрывает данные пользователя (только `_id` и роли).

**Как перенести.** Поле-счётчик в модели пользователя, `$inc` на выходе и при смене пароля, сравнение `tv` при обновлении сессии. Тесты: выход, выход на другом устройстве, чужие сессии, `alg: none`, HS256, чужие `iss`/`aud`, токен другого типа.

**Оговорки.** Access-токен жив до 15 минут после отзыва (компромисс stateless-проверки). Меняя секреты, учтите, что все выданные токены станут недействительными.

## 17. Токены в SPA: access в памяти, refresh в HttpOnly-cookie с узким `Path` {#17}

**Суть.** Access-токен живёт в переменной (сервис в памяти), не в `localStorage`. Refresh-токен в cookie `HttpOnly`, `SameSite=Strict`, `Secure`, `Path=/rest/auth`: браузер шлёт её только на `/auth/*`. Эта cookie открывает `refresh` и `sign-out`, остальные маршруты принимают лишь Bearer. При старте app initializer зовёт `refresh` и возвращает сессию; интерсептор при 401 один раз обновляет токен и повторяет запрос (параллельные запросы делят одно обновление через `share()`).

**Польза.** XSS не достаёт токены из хранилища; CSRF не работает, потому что cookie не служит сессией для API; перезагрузка страницы сессию не теряет. Решение зафиксировано в [ADR 0012](adr/0012-tokens-in-memory-and-httponly-cookie.md).

**Как перенести.** Эндпоинт `refresh` по cookie, `Path` cookie на auth-маршруты, `AuthGuard` без cookie-фолбэка, `AccessTokenStore`, `provideAppInitializer`, функциональный интерсептор с `share()`. Тесты: параллельные 401, неудачное обновление, отсутствие записи в `Storage`.

**Ротация.** Каждый refresh выдаёт новый токен (`jti`) в сессии устройства (`sid`); предъявленный второй раз старый токен значит кражу, и сессия удаляется целиком. Окно в 10 секунд для двух вкладок: второй запрос получает access-токен без новой cookie. Вкладки синхронизируются через `BroadcastChannel`.

**Оговорки.** На одном origin с SSR лучше серверная сессия; сессия скользящая, абсолютного предела нет.
