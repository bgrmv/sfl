# Skills и особенности работы агентов

Учёт agent skills, применённых к проекту, и договорённостей по работе с агентами. Выбор и правила аудитов — история [S11.8](backlog/E11-dx-docs/S11.8.md). Общая картина проекта — [PROJECT.md](PROJECT.md).

## Правила

- Сторонний skill читают целиком до установки; фиксируют источник и версию (коммит или тег). Skill, который ходит в сеть или меняет файлы вне репозитория, не принимается.
- Skills проекта лежат в `.claude/skills/`; личные помечаются «личный».
- Аудит: агент только читает код, пишет отчёт в `docs/audits/`, исходники не правит. Найденное оформляется историями бэклога (правило 6 из [README бэклога](backlog/README.md)). Формат отчёта, серьёзность и карта доменных областей — в skill `audit-report`.

### Рассмотрены и не приняты

Полный список кандидатов с причинами — [skills-candidates.md](skills-candidates.md). Коротко: Superpowers, ECC и фреймворки целиком (конфликтуют с `AGENT.md` и бэклогом), Trail of Bits (не по профилю), внешние a11y-skills (скрипты и сеть или нет лицензии), `theme-factory` (слайды).

Отличия соседних: `/code-review` смотрит дифф, `audit-report` задаёт порядок аудита всей кодовой базы; `/security-review` ищет уязвимости, `security-and-hardening` даёт чек-лист для аудита всего кода; `frontend-design` помогает выбрать направление, `material-theme` — перенести его в тему.

## Особенности и договорённости

- Единый файл правил для агентов — [AGENT.md](../AGENT.md); `CLAUDE.md` и `AGENTS.md` только ссылаются на него.
- Агент не коммитит и не пушит без просьбы владельца.
- Папки `_backups/`, `_dumps/`, `ssl/` агенты не читают.
- Документация и бэклог на русском, сообщения коммитов на английском.
