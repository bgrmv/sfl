# Формы на signal forms, `@ngrx/signals` — единственный стор

Статус: принято
Дата: 2026-11-13

Формы клиента переводятся с реактивных форм на signal forms (`@angular/forms/signals`, `form()` в Angular 22 — публичный API). Форма владеет черновиком, который пользователь правит, и на `submit` отправляет его на сервер. Источник правды для данных лиги — сервер; клиентский стор — их кэш и общий контекст между страницами. Правила проверки пишутся один раз на zod ([S1.12](../backlog/E01-dependency-upgrades/S1.12.md)) и подключаются к форме через `validateStandardSchema`, а не дублируются в клиенте руками.

Единственный стор клиента — `@ngrx/signals` ([0004](0004-client-state-ngrx-signals.md)). `@ngrx/store` (`provideStore()` без редьюсеров) и `store-devtools` удаляются, `@ngrx/component-store` в «капитанах» заменяется на `signalStore` ([S3.7](../backlog/E03-architecture/S3.7.md)). Переход на signal forms идёт по одной форме, начиная с пилота ([S3.16](../backlog/E03-architecture/S3.16.md)).

## Рассмотрено

- **Остаться на реактивных формах.** Работает, но типы слабее, а правила валидации приходится дублировать на клиенте и сервере.
- **Хранить черновики форм в сторе** (как сейчас в `new-game`). Смешивает данные лиги и состояние ввода; форма с валидацией справляется с этим сама.

## Последствия

Совместимость signal forms с Angular Material (`mat-form-field`) не проверена: поэтому сначала пилот на одной форме, а массовый переход — после его результатов. Правила матча (капитан, позиция) уезжают из стора `new-game` в схему формы.
