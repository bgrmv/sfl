# Один матч редактирует один администратор: аренда в базе

Статус: принято
Дата: 2026-11-16
Утверждено владельцем: 2026-11-16

Матч вводят вручную, иногда долго (составы, голы, порядок). Если двое открыли один матч, правки одного молча затрут правки другого, а два подтверждения ([S10.35](../backlog/E10-product-features/S10.35.md)) потеряют смысл: человек подтвердил одно содержимое, а оно уже другое.

## Решение

**Аренда (lease) в базе, версия как второй рубеж, WebSocket только для уведомлений.**

1. У матча в «Новый» и «Черновик» есть поле `lock: { accountId, acquiredAt, expiresAt }`. Взять аренду можно одной атомарной операцией: `updateOne({ _id, $or: [{ lock: null }, { 'lock.expiresAt': { $lt: now } }, { 'lock.accountId': me }] }, { $set: { lock } })`. Если ничего не изменилось, ответ `409 Conflict` с именем владельца и временем окончания.
2. Клиент продлевает аренду «пульсом» (heartbeat) каждые 30 секунд на 2 минуты и отпускает при закрытии матча. Закрыл вкладку или пропала сеть: аренда истекает сама, матч свободен через 2 минуты.
3. Сохранение принимается только от владельца аренды и только с текущей версией документа (`version` или `updatedAt`, заголовок `If-Match`). Это второй рубеж: аренда могла истечь, пока человек думал.
4. **Любое изменение содержимого черновика очищает подтверждения.** Подтверждение относится к конкретной версии матча.
5. Подтверждать матч можно, не беря аренду на редактирование: подтверждающий только читает. Публикация («Опубликован») возможна, когда есть подтверждения от двух и более разных людей на текущей версии; правило проверяет домен, статус нельзя выставить напрямую через PATCH.
6. WebSocket ([S10.10](../backlog/E10-product-features/S10.10.md)) добавляет только push «матч занят» и «матч освободился». Пока его нет, клиент опрашивает состояние раз в 30 секунд вместе с пульсом.

## Почему так

- Состояние в базе переживает перезапуск сервера, переподключение клиента и работает при нескольких экземплярах.
- Атомарный `updateOne` с условием не требует транзакции и блокировок на минуты.
- Версия защищает и от случая, когда аренды нет (старый клиент, ручной запрос).
- WebSocket не обязателен для корректности, он улучшает отклик, и его можно добавить позже (он в P4).

## Рассмотрено

- **Только WebSocket (presence).** Состояние вне базы, теряется при разрыве, при реконнекте двое могут зайти одновременно; корректность зависит от канала.
- **Только оптимистичная версия.** Двое работают впустую, конфликт обнаруживается в конце и правки одного пропадают.
- **Долгая транзакция MongoDB.** Транзакции не держат минутами ([ADR 0014](0014-mongodb-replica-set.md)); для публикации она нужна, для аренды нет.
- **Блокировка в памяти сервера.** Теряется при перезапуске и не работает при двух экземплярах.

## Последствия

- Нужны поля `lock` и `version` в схеме матча (`@sfl/schemas`), маршруты `POST /games/:id/lock`, `DELETE /games/:id/lock`, строки в `test/api/access.test.ts`.
- Тесты первыми ([ADR 0013](0013-tests-first-then-domain-then-local.md)): два администратора берут один матч, второй получает 409; истёкшая аренда свободна; сохранение без аренды и со старой версией отклоняется; правка очищает подтверждения; один человек не подтверждает дважды; публикация без двух подтверждений невозможна.
- Решение владельца 2026-11-16: заполнивший матч **может** быть одним из двух подтверждающих, но нужны «ещё глаза»: публикация требует минимум двух разных людей, то есть как минимум одного подтверждающего, который не заполнял матч.
- Открыто: срок аренды и частота пульса (предложено 2 минуты и 30 секунд).
