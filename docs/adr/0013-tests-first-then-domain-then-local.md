# Порядок разработки: сначала тесты, потом домен, потом локальное

Статус: принято
Дата: 2026-11-15

Любая работа идёт в одном порядке, на клиенте и на сервере:

1. **Тесты первыми.** Сначала тест, который описывает поведение (красный), потом код, который его проходит. Для расчёта статистики, прав и публикации матчей тест обязателен до кода; для вёрстки достаточно теста на состояния и доступность.
2. **Потом домен.** Правила лиги живут в чистом TypeScript без Angular, Nest и Mongoose: очки и системы счёта, MVP, статусы матча и подтверждения, рейтинги, сезоны, награды. Код домена лежит в общем пакете `packages/domain` ([ADR 0009](0009-pnpm-workspace-separate-lockfiles.md)), его читают сервер и клиент, поэтому цифры на странице «Как начисляются очки», в «Try it» и в рейтинге считаются одной функцией.
3. **Потом локальное.** Только после этого сторы, контроллеры, репозитории, компоненты и стили: тонкие адаптеры вокруг домена.

**DDD в мере, нужной лиге.** Ограниченные контексты: Матч (агрегат `Game`: события, составы, подтверждения, публикация и отзыв), Рейтинг (проекции по сезону и системе), Люди (игрок, аккаунт, согласия, привязка), Сообщество (правила, предложения, голосования, комментарии, фото). Язык кода — термины из [GLOSSARY.md](../../GLOSSARY.md); меняется правило — сначала глоссарий, потом тест. Агрегаты меняются только командами, рейтинги читаются только запросами (CQRS, [PROJECT.md](../PROJECT.md), раздел 3.2). Event sourcing не нужен.

**Тестовая пирамида.** Много быстрых тестов домена (Vitest, без базы), средний слой API-тестов на `mongodb-memory-server`, компонентные тесты клиента на состояниях и доступности, мало сквозных. Golden-master на анонимизированном наборе ([S2.2](../backlog/E02-tests-ci/S2.2.md)) остаётся стражем расчёта: домен нельзя менять, пока он зелёный или пока расхождение не объяснено.

## Рассмотрено

- **Код сначала, тесты после.** Быстрее на старте, но расчёт рейтингов уже ломался молча (`it.fails` в наборе тестов), и каждое правило лиги имеет исключения.
- **Домен внутри Nest и внутри Angular отдельно.** Цифры на клиенте и на сервере разойдутся, а «Try it» и «Compare» перестанут совпадать с рейтингом.
- **Полный DDD и `@nestjs/cqrs` сразу.** Лишняя церемония для одного сервиса; шину решаем отдельной историей ([эпик 3](../backlog/E03-architecture/)), структура файлов уже разделяет команды и запросы.

## Последствия

Пакет `packages/domain` создаёт уже существующая [S3.1](../backlog/E03-architecture/S3.1.md); она становится опорной для экранов эпика 10. В [AGENT.md](../../AGENT.md) добавлено правило порядка. Новая история начинается с критериев, которые можно превратить в тест. Пулл-реквест, где нет теста на новое поведение, не принимается.
