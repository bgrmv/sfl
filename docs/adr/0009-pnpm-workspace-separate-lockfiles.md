# pnpm workspace с отдельными lock-файлами и общим пакетом `@sfl/schemas`

Статус: принято
Дата: 2026-11-13

Репозиторий — pnpm workspace (`client`, `server-nest`, `packages/*`), один `pnpm install` в корне ставит всё. Общие для клиента и сервера значения и формы API (enum статуса матча, позиции, цвета команды, статуса игрока; DTO команды и статистики игрока) объявлены один раз в `packages/schemas` (`@sfl/schemas`) и подключаются как `workspace:*`. Пакет собирается `tsc` в **ESM** и читается из `dist/`: клиент (Angular) использует ESM напрямую, сервер остаётся CommonJS и загружает его через `require` (как и ESM-пакеты Nest 12, [0008](0008-nest-12-express-5-commonjs.md)). Сборка пакетов (`pnpm build:packages`) входит в `pnpm check` и запускается перед `dev`, `build` и тестами.

У каждого проекта **свой lock-файл и свой `node_modules`** (`shared-workspace-lockfile=false` в корневом `.npmrc`).

## Рассмотрено

- **Общий lock-файл и один `node_modules` в корне.** Классический workspace. Отклонено: `node_modules` лежат в томах dev-контейнера (бинарники собираются под Linux, на хосте Windows их быть не должно), общий каталог в корне пришлось бы вынести в том и перенастроить сохранение. Клиент и сервер сейчас обновляются независимо ([S1.7](../backlog/E01-dependency-upgrades/S1.7.md), [S1.13](../backlog/E01-dependency-upgrades/S1.13.md)); общий lock связал бы их версии.
- **Пакет как TypeScript-исходники без сборки** (`exports` на `src/*.ts`). Не работает для сервера: Node не применяет типизацию для файлов внутри `node_modules`, а `nest build` не принимает исходники вне `rootDir`.
- **Дублировать типы в клиенте и сервере** (как было). Отклонено: уже накопились расхождения (лишний статус `furture` на клиенте, позиция без `null` в клиентском типе, `goalsByAuto` необязателен на сервере).

## Последствия

Каждый новый пакет в `packages/` нужно добавить в `docker-compose.yml` как том для его `node_modules` и пересобрать контейнер. Пока `dist/` пакетов не собран, клиент и сервер не стартуют: этим занимаются `pre`-скрипты и `pnpm check`. Пакет `packages/domain` ([S3.1](../backlog/E03-architecture/S3.1.md)) появится по тому же образцу. В [S1.12](../backlog/E01-dependency-upgrades/S1.12.md) в `@sfl/schemas` переедут схемы zod, а типы будут выводиться из них.
