# Монолит Nest на VPS: SPA и API за Caddy, SSR отложен

Статус: принято; уточнено 2026-11-15 (по результатам спайка S4.1 SSR отложен)
Дата: 2026-10-25

Один процесс Nest отдаёт `/rest/*`, и в нём же живут cron и websockets. Клиент — Angular SPA, статический бандл на том же домене. Запуск — Docker Compose (`edge-caddy → app → [mongodb]`) на общем VPS, деплой — GitHub Actions → GHCR → ssh. SFL изолирован в `/opt/sfl/`, общий прокси — в `/opt/edge/`. Решение выбрано ради цены always-on инстанса, полного контроля и того, что cron и websockets нужны. Детали и прототип — [S4.1](../backlog/E04-migration-design/S4.1.md).

Исходно (2026-10-25) планировалось, что тот же процесс рендерит Angular через `AngularNodeAppEngine` (SSR). Прототип показал, что это работает, но единственный довод за SSR — превью ссылок, а их владелец закрывает другим путём (memmo и PWA). Поэтому **первый этап — без SSR**, SSR остаётся опцией ([S7.5](../backlog/E07-vps-hosting/S7.5.md)).

## Рассмотрено

- **A. SPA + Nest API на одном домене (выбрано).** Клиент — статика (Caddy или `ServeStaticModule`), `/rest/*` — Nest. Один домен, CORS не нужен.
- **B. Монолит Nest + Angular SSR.** Рабочий вариант (замеры ниже), отложен: цена не окупается без внешней потребности в превью и индексации.
- **Angular на Netlify → Supabase напрямую (RLS, Edge Functions), без своего бэкенда.** Netlify не держит постоянные процессы, а cron и websockets нужны. Сервер команде понятнее, чем RLS и SQL-функции.
- **NestJS в Netlify Functions.** Холодный старт, лимит времени на пересчёт статистики, нет websockets.
- **PaaS (Render, Railway, Fly.io).** Рабочий вариант, отклонён по цене за always-on инстанс и ради контроля.
- **Coolify на VPS.** Лишний слой со своей памятью и обновлениями; Compose + Caddy проще.

## Последствия

NestJS остаётся, поэтому его обновление ([S1.7](../backlog/E01-dependency-upgrades/S1.7.md)) и улучшение архитектуры сервера нужны. Образ ([S7.1](../backlog/E07-vps-hosting/S7.1.md)) содержит браузерный бандл и Nest без серверного бандла Angular. Лимиты памяти для [S7.2](../backlog/E07-vps-hosting/S7.2.md) — предварительные, их надо проверить в контейнерах на первом образе.

## Результаты спайка (S4.1)

Прототип собран 2026-11-15 на отдельной ветке и **не сохранён**: код удалён, ветка снесена, итог — этот раздел. Docker в dev-container нет, поэтому замеры сняты с обычного процесса `node` (NODE_ENV=production, Node 22, MongoDB 7 в соседнем контейнере, 0.5 МБ данных), а не с контейнеров.

**Сервер.** MVPS (mvps.net), VPS BASIC, KVM, Ubuntu 26.04, 2 vCPU, 4 GB RAM, 50 GB NVMe, €8.47 в месяц, автобэкапы провайдера включены.

**Подтверждено.** Один процесс Nest отдавал `/rest/*` и рендерил Angular с Material: `/`, `/players`, `/games` возвращали разметку с `mat-*`, `/sign-in` — клиентский shell, неизвестный путь — `404`, `/rest/games` отвечал из того же процесса.

Итого SFL около 1.7 ГБ, остаётся более 2 ГБ для 1–2 соседних проектов. Проверить в контейнерах на первом образе и поправить по факту.

## Сравнение вариантов

|                  | A. SPA + Nest API за Caddy                              | B. Монолит Nest + SSR                                                                     |
| ---------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Раздача клиента  | статика, Caddy или `ServeStaticModule`                  | Angular рендерится в процессе Nest                                                        |
| Память `app`     | около 160 МБ                                            | 160 МБ в простое, пик около 490 МБ                                                        |
| Сложность        | минимальная                                             | мост ESM/CJS, `NG_ALLOWED_HOSTS`, SSR-безопасность каждого обращения к браузеру, гидрация |
| Первая отрисовка | пустой shell, затем данные                              | готовая разметка (после переделки хранилищ)                                               |
| Превью ссылок    | не даёт, закрывается memmo и PWA                        | даёт после Open Graph-тегов                                                               |
| Отказ            | падение API не мешает отдать клиент (если отдаёт Caddy) | один процесс на всё                                                                       |
| Cookie и CORS    | один домен, CORS не нужен                               | то же                                                                                     |

## Что нужно знать, если вернёмся к SSR (S7.5)

- **Мост ESM/CJS.** Nest собирается в CommonJS ([ADR 0008](0008-nest-12-express-5-commonjs.md)), серверный бандл Angular — ESM. TypeScript превращает `import()` в `require()`, поэтому бандл загружался через `new Function('url', 'return import(url)')`. Статика бандла браузера и SSR-обработчик подключались через `app.use` **до** маршрутов Nest, пути `/rest` пропускались явно; `ServeStaticModule` при этом отключался, потому что его `*path` перехватывает все страницы.
- **Хосты.** Angular проверяет заголовок Host (защита от SSRF): без `NG_ALLOWED_HOSTS` (через запятую, например `sfl.com,localhost`) каждый запрос получает `400` с текстом `Header "host" … is not allowed`. За прокси добавить `NG_TRUST_PROXY_HEADERS`.
- **Клиент.** `LocalStorageService` падал на сервере (`localStorage` нет), нужен `document.defaultView?.localStorage`; восстановление сессии по refresh-cookie выполнять только в браузере; клиенту нужен `@types/node` для точки входа сервера.
- **Highcharts.** На сервере падает `TypeError: this.getChartFactory(...) is not a function` (`highcharts-angular` 5 с ленивым `import('highcharts')` в Node): графики рендерить только в браузере.
- **Данные.** `/` и `/games` на сервере отдаются без данных: хранилища ждут `delay(500)` и догружаются после гидрации. Чтобы SSR что-то давал, их надо переделать на ожидание загрузки (`PendingTasks` или resolver).
- **Прочее.** Неизвестные пути отдают `404` стандартным ответом Express, а не страницей Angular ([S8.5](../backlog/E08-security-privacy/S8.5.md)); Open Graph-тегов нет; в production Nest слушает по http, а refresh-cookie помечена Secure: на `localhost` она работает, на другом хосте по http браузер её не примет. Серверный бандл — 2.5 МБ `.mjs` (13 МБ с ассетами).
