# Архитектурные решения (ADR)

Записи о решениях, которые трудно отменить, неочевидны без контекста и выбраны из реальных альтернатив. Формат и критерии: skill `domain-modeling` (`ADR-FORMAT.md`). Язык проекта и правила расчёта лиги — не ADR, а [GLOSSARY.md](../../GLOSSARY.md).

## Как писать

Файл `NNNN-короткое-название.md`, номер следующий по порядку, не меняется. Одна запись — одно решение, 1–3 абзаца. Разделы «Рассмотрено» и «Последствия» — только если добавляют ценности.

```md
# Короткое название решения

Статус: принято | предложено | заменено ADR-NNNN | отклонено
Дата: ГГГГ-ММ-ДД

Контекст и решение: что решили и почему (1–3 предложения).

## Рассмотрено
Отклонённые варианты, если причина отказа неочевидна.

## Последствия
Неочевидные следствия, если есть.
```

Решение пересматривается новой записью, старая получает статус «заменено ADR-NNNN». Записи не удаляют.
