# MongoDB работает как replica set ради транзакций

Статус: принято
Дата: 2026-11-15

Публикация матча, подтверждения и отзыв затрагивают несколько документов сразу: матч, проекции рейтингов, журнал. Это должно быть одной операцией: либо всё записано, либо ничего. Транзакции MongoDB работают только на replica set, поэтому сервер базы запускается как replica set из одного узла (`rs0`) в dev-container, в тестах и на VPS.

**Что меняется.** Docker-образ `mongo:7.0` запускается с `--replSet rs0`, при первом старте выполняется `rs.initiate()`; строка подключения получает `replicaSet=rs0`. Тесты используют `MongoMemoryReplSet` вместо одиночного сервера. Команды домена `confirm`, `publish`, `revoke` выполняются в сессии с `withTransaction`, команды идемпотентны.

**Чем платим.** Чуть больше памяти и один шаг при инициализации; резервные копии остаются `mongodump` ([S6.1](../backlog/E06-data-migration/S6.1.md)), но восстановление делается на replica set. Отказоустойчивость одного узла не даёт, она и не нужна: цель только транзакции.

## Рассмотрено

- **Без транзакций, порядок записей и компенсации.** Проще на старте, но отзыв публикации оставляет рейтинги в промежуточном состоянии при сбое; чинить такое вручную дороже.
- **Пересчитывать проекции на лету и не хранить их.** Транзакции не нужны, но страницы рейтингов станут медленнее, а подтверждение матча по-прежнему меняет несколько документов (матч, журнал).
- **Кластер из трёх узлов.** Лишняя цена для лиги из ~40 человек.
