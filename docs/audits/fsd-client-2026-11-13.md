# Аудит клиента на соответствие FSD (skill `feature-sliced-design`)

Дата: 2026-11-13. Формат — skill `audit-report`, правила — skill `feature-sliced-design` (FSD v2.1). Исходники не менялись.

Базовая проверка: `pnpm check --all` проходит (15 шагов, Node 22.23: в контейнере пока 22.16, нужна пересборка). Проверен только `client/src`, без `*.spec.ts`: 111 `.ts`-файлов, разбор импортов скриптом по алиасам `@entities`, `@features`, `@shared`, `src/...` и относительным путям.

## 1. Резюме

- **Вывод: это FSD по названиям папок, а не по правилам.** Слои названы верно, но половина кода лежит не там, где требует методология, и ни у одного слайса нет публичного API.
- Находок: **6** (все подтверждены чтением кода или подсчётом импортов). Высоких 0, средних 4, низких 2.
- Что в порядке: **импортов вверх по слоям нет** (проверено по всем файлам: `entities` и `shared` не ссылаются на `features`, `widgets`, `pages`, `app`); `shared` не зависит от верхних слоёв; `app` собирает маршруты.
- Главные проблемы:
  1. **Слои `pages` и `widgets` лежат внутри `entities`** (`entities/games/pages`, `entities/games/widgets`, `entities/players/pages`): в `entities` ~100 из 180 файлов. В `pages/` всего 3 страницы.
  2. **Нет публичного API слайсов.** `index.ts` есть только у `entities/games`, `entities/players`, `entities/teams`, `entities/captains` и общий «бочонок» `features/index.ts`; у 7 слайсов `features`, 2 `widgets` и 3 `pages` его нет. В `entities` 56 глубоких импортов мимо `index.ts` (например `@entities/games/types`: 18, `@entities/players/services/players.service`: 9).
  3. **Кросс-импорты между сущностями:** `games` ↔ `players` (6 + 13 файлов), `games` → `teams`, `teams` → `games`, `players` → `captains`, `utils` ↔ `games`. Цикл `games ↔ players` уже записан в [S3.3](../backlog/E03-architecture/S3.3.md).
- Правила и инструменты проверки: линтер границ слоёв не настроен ([S3.8](../backlog/E03-architecture/S3.8.md)).

## 5. Что не проверено

- `*.spec.ts` и `shared/ui`: структурный разбор только по `.ts` без шаблонов; импорты в шаблонах (`imports: [...]` компонентов) учтены через `.ts`.
- Steiger (`npx steiger src`) не запускался: skill советует его, но это установка пакета; результаты выше получены своим разбором импортов.
- Раскладка `pages` против `entities/*/pages` оценена по правилам skill; решение, что страница игрока или матча «страница, а не сущность», остаётся за владельцем.
