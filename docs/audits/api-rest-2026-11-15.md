# Аудит REST API: лексика, семантика, топология

Дата: 2026-11-15. Контекст: подготовка к [S3.19](../backlog/E03-architecture/S3.19.md). Формат — skill `audit-report`.

База: `pnpm check` проходит по всем шагам (линт, типы, тесты, сборка, audit, gitleaks). Исходники не менялись.

**Об инструментах.** Скилла по OpenAPI или REST среди подключённых нет. Мерки взяты из первоисточников: RFC 9110 (семантика методов и кодов), RFC 9457 (формат ошибки), OpenAPI 3.x (`operationId`, теги, ответы), руководства Microsoft и Google по REST API (ресурсы во множественном числе, глаголы только для действий). Каждая находка проверена чтением кода; воспроизведение запросами не делалось.

## 1. Резюме

Проверено: 8 контроллеров, 27 маршрутов, вызовы клиента, `app.setup.ts`, формат ответа ([ADR 0011](../adr/0011-result-response-format.md)).

Находок: **16** (высоких 2, средних 8, низких 6). Главное:

1. **Клиент вызывает два маршрута, которых на сервере нет:** `POST /players/captains` и `POST /players/list`. Пока их закрывает мок (`useMock = true` в `CaptainsService`), но это мина.
2. **Swagger описывает не то, что отдаёт API.** Документация не знает про обёртку `{ ok, data }`; ошибки описаны как голые коды Nest.
3. **Семантика кодов нарушена** в нескольких местах: `DELETE` с `201`, `POST` создания с `200`, «действия» отдают `{ success: 'OK' }`.
4. **Лексика смешана:** теги `player`/`user` в единственном числе при путях во множественном, глаголы в путях, `roles` и `users/test-users` без `Public`/`Roles` и без реальной функции.
5. **Две ручки `PUT` и `PATCH`** на игру с разными DTO и неверным описанием в Swagger.

## 3. Находки

Серьёзность по `audit-report`. Все «проверено» — чтением кода.

## 5. Что не проверено

- Поведение запросов вживую (нет воспроизведения; всё чтением кода и тестов).
- Заголовки кэширования (`ETag`, `Cache-Control`) и пагинация: списки отдаются целиком, лимитов нет.
- Совместимость с внешними потребителями: известен только наш клиент.
