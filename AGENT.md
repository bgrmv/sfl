# AGENT.md — правила проекта SFL

Один файл для всех ИИ-агентов (Claude Code, Copilot и др.). Подробности — по ссылкам, здесь только то, что нужно, чтобы начать работу.

## Проект

SFL — приложение для любительской футбольной лиги: Angular SPA + NestJS API + MongoDB. Архитектура: [Project_Architecture_Blueprint.md](Project_Architecture_Blueprint.md). Стек, методологии (FSD, CQRS) и обязанности: [docs/PROJECT.md](docs/PROJECT.md). Применённые skills: [docs/skills.md](docs/skills.md). План работ: [docs/backlog/README.md](docs/backlog/README.md). Архитектурные решения и причины: [docs/adr/](docs/adr/README.md). Язык и правила лиги (матч, трансфер, система счёта, MVP): [GLOSSARY.md](GLOSSARY.md); меняешь правило расчёта — сначала обнови его там.

| Папка | Что это |
|---|---|
| `client/` | Angular SPA (слои FSD: `app`, `pages`, `widgets`, `features`, `entities`, `shared`) |
| `server-nest/` | основной API: NestJS, Mongoose |
| `packages/` | общие пакеты workspace: `@sfl/schemas` (enum и DTO API для клиента и сервера) |
| `docs/backlog/` | истории по эпикам `E00`–`E12`, статусы в `README.md` |

Позже появятся `packages/domain`, `Dockerfile`, `docker-compose.yml`, `Caddyfile` (эпики 3 и 7).

## Окружение

Работаем в dev-container; Node.js и MongoDB на хосте не нужны. Пакетный менеджер — **pnpm** (через corepack). База: `mongodb://mongodb:27017`, БД `sfl` (`server-nest/.env`, значения dev-only). Изменили настройки контейнера — см. таблицу «что делать» в [README.md](README.md).

## Команды

**Общие пакеты (`packages/*`) читаются клиентом и сервером из `dist/`: `pnpm build:packages` из корня их собирает; `pnpm check` и скрипты `dev`, `build`, `test` делают это сами.** Меняешь форму API — меняй её в `@sfl/schemas`, а не в клиенте и сервере по отдельности ([ADR 0009](docs/adr/0009-pnpm-workspace-separate-lockfiles.md)).

**Перед коммитом запускай из корня `pnpm check`** ([scripts/check.mjs](scripts/check.mjs), ~1 минута): lint без `--fix`, типы, тесты и prod-сборка обоих пакетов, падает на первой ошибке. Флаги: `--all` (сводка по всем шагам), `--skip=<шаг,...>`, `--only=client|server|<шаг>`, `--include-known`. Шаги, которые падают по известным причинам, пропускаются с выводом причины; список — константа `KNOWN` в скрипте (сейчас пуст).

Остальные команды запускай из папки пакета.

| Действие | `client/` | `server-nest/` |
|---|---|---|
| Установка | `pnpm install` из корня ставит всё (workspace) | то же |
| Запуск | `pnpm dev -- --host 0.0.0.0` (https, порт 4200) | `pnpm start:dev` (порт 3001) |
| Линт | `pnpm lint` | `pnpm lint` (с `--fix`) |
| Типы и сборка | `pnpm build` | `pnpm build` |
| Тесты | `pnpm test` (Vitest через `ng test`, браузер не нужен); один прогон: `pnpm exec ng test --watch=false` | `pnpm test` (vitest, watch); один прогон: `pnpm vitest run` |
| Prod-сборка | `pnpm build:prod` | `pnpm build` |

## Соглашения

- Клиент: слои FSD, импорты только «вниз» (`pages` → `widgets` → `features` → `entities` → `shared`). Состояние — `@ngrx/signals`.
- Права: новый серверный маршрут по умолчанию доступен только `ADMIN`; открыть его можно `@Public()` или `@Roles(...)`, и тогда нужна строка в матрице `test/api/access.test.ts` ([docs/PROJECT.md](docs/PROJECT.md), раздел 5.1).
- Ошибки API: бросай исключения Nest **экземплярами** (`throw new NotFoundException()`), не глотай ошибки в сервисах; формат ответа задаёт глобальный фильтр ([docs/PROJECT.md](docs/PROJECT.md), раздел 5.2).
- Серверные тесты: юнит-тесты рядом с кодом (`src/**/*.test.ts`), API-тесты в `server-nest/test/api/` на `mongodb-memory-server` (внешняя база не нужна; первый запуск скачивает бинарник mongod). Известные дефекты помечены `it.fails` со ссылкой на историю: исправил дефект — убери `.fails`. Покрытие: `pnpm test:coverage` (порог 80% на расчёте статистики).
- Сервер: модуль на сущность (контроллер, сервис, схема Mongoose, DTO). Валидация сейчас valibot, переходим на zod ([S1.12](docs/backlog/E01-dependency-upgrades/S1.12.md)): новый код пиши с учётом этого.
- Коммиты: `feat:` / `fix:` / `chore:` / `docs:` с областью и ID истории, как в `git log`: `fix(server): ... (S0.4)`. Сообщения на английском, документация и бэклог на русском.
- Комментарии в коде — только когда причина неочевидна.

## Запреты

- Не коммитить секреты, `.env`, бэкапы, дампы и персональные данные (хеши паролей, email). Папки `_backups/`, `_dumps/`, `ssl/` не читать содержимым и не публиковать.
- Не трогать прод-базу и прод-окружение: только локальный MongoDB.
- Не делать force-push в `main`, не переписывать опубликованную историю.
- Не коммитить и не пушить, пока владелец не попросил.
- Не добавлять зависимости без причины в истории: версии выбираются в [S1.1](docs/backlog/E01-dependency-upgrades/S1.1.md).

## Definition of done

1. Все ACs истории отмечены `- [x]`.
2. `pnpm check` проходит (линт, типы, тесты, сборка).
3. Документация обновлена, включая этот файл, если изменились команды, структура или соглашения.
4. В индексе бэклога статус ❌ заменён на ✅ в том же коммите или PR.

## Работа с бэклогом

Единственный источник статусов — таблицы в [docs/backlog/README.md](docs/backlog/README.md).

1. **Следующая история:** первая ❌ (не ⛔) с наивысшим приоритетом (P0 → P3), у которой все зависимости ✅. При равенстве — меньший номер эпика, затем истории. P4 (сборка, деплой, CI/CD) — только по прямой просьбе.
2. **Перед началом** прочитай файл истории и файлы её зависимостей.
3. **Во время работы** отмечай ACs в файле истории.
4. **Закрытие:** все ACs отмечены → ❌ на ✅ в индексе, в том же коммите или PR.
5. **AC невыполним или устарел:** не отмечай его, добавь в конец файла истории раздел `## Заметки` с причиной, статус оставь ❌.
6. **Новая работа** — новая история `S<эпик>.<номер>.md` в папке эпика и строка в индексе. ID существующих историй не меняй, файлы не удаляй.

## Поддержка файла

- Меняешь команды, структуру или соглашения — обнови этот файл в том же PR.
- В шаблоне PR есть пункт «нужно ли обновить AGENT.md».
- В конце каждой фазы дорожной карты файл перечитывается, устаревшее удаляется.
- Держи файл в пределах ~200 строк: детали — в README, blueprint и ADR по ссылкам.
