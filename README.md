# SFL

**Любительская футбольная лига**: сайт с матчами, игроками и рейтингами. Лига играет каждую субботу с 1980 года, и ни одна неделя не пропущена. Здесь хранится вся эта история: кто с кем играл, кто сколько забил и отдал, кто лучший в сезоне и в карьере.

Приложение: Angular SPA + NestJS API + MongoDB.

## Что умеет

- **Матчи.** Две команды, капитаны по очереди выбирают составы (драфт), к матчу привязаны счёт, статус (новый, черновик, опубликован) и статистика каждого участника.
- **Игроки.** Карточка игрока с голами (ногой, головой, пенальти), передачами, автоголами, позицией и наградами MVP.
- **Рейтинги.** Две системы счёта (старая и новая, с бонусом по позиции), показатели за сезон и за всю карьеру. В них входят только опубликованные матчи.
- **Капитаны.** Список капитанов и выбор капитана на матч.
- **Администратор лиги** ведёт матчи и игроков; остальные только смотрят.

Правила расчёта (вес гола, трансфер, MVP, очки) описаны в [GLOSSARY.md](GLOSSARY.md). Это источник истины для кода и тестов: меняете правило — сначала правьте там.

## Быстрый старт

Нужны Docker (Docker Desktop или Rancher Desktop) и VS Code с расширением Dev Containers. Node.js и MongoDB на машине ставить не нужно.

1. В hosts добавьте строку `127.0.0.1 sfl.com` (на Windows: `C:\Windows\System32\drivers\etc\hosts`). Это адрес для локальной разработки, не продакшен.
2. Откройте репозиторий в VS Code и выполните **Dev Containers: Reopen in Container**. Первая сборка сама поставит зависимости, сертификат, `.env` и тестовые данные.
3. Сервер: `cd server-nest && pnpm start:dev`. Предупреждение `⚠ backup: no encrypted prod backup` в начале вывода — не ошибка: оно про бэкап прод-базы, который ведёт владелец, для локальной работы он не нужен.
4. Клиент: `cd client && pnpm dev` (хост `0.0.0.0` задан в `angular.json`, иначе Docker не пробросит порт)
5. Откройте `https://sfl.com:4200` и один раз примите самоподписанный сертификат. То же для `https://sfl.com:3001/rest` (Swagger). Порт обязателен.
6. Войдите как `admin@sfl.local` / `admin`. Этот администратор создаётся при каждом запуске сервера в локальной разработке, даже если в базе копия прода. Данные seed синтетические.

Не получилось: [Troubleshooting](docs/development.md#troubleshooting). Без контейнера: [docs/development.md](docs/development.md#without-the-dev-container).

## Команды

Из корня репозитория:

| Команда               | Что делает                                                               |
| --------------------- | ------------------------------------------------------------------------ |
| `pnpm check`          | линт, типы, тесты, prod-сборка, аудит зависимостей и секретов; ~1 минута |
| `pnpm check --all`    | то же, но не останавливается на первой ошибке, а даёт сводку             |
| `pnpm build:packages` | собирает общие пакеты (`dist/` нужен клиенту и серверу)                  |

В пакетах: `pnpm test`, `pnpm lint`, `pnpm build`. Подробности — в [server-nest/README.md](server-nest/README.md) и [AGENT.md](AGENT.md). Перед каждым коммитом запускайте `pnpm check`; pre-commit хук проверяет только изменённые файлы.

## Из чего состоит

| Папка            | Что это                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| `client/`        | Angular 22, слои FSD (`app`, `pages`, `features`, `entities`, `shared`), состояние на `@ngrx/signals`        |
| `server-nest/`   | NestJS 12: модуль на сущность (контроллер, сервис, схема Mongoose, DTO), права по ролям                      |
| `packages/`      | `@sfl/schemas`: формы данных API на zod; `@sfl/domain`: чистый расчёт статистики (оба для клиента и сервера) |
| `docs/`          | проект, бэклог, архитектурные решения (ADR), аудиты                                                          |
| `.devcontainer/` | окружение разработки: Node 22, pnpm, MongoDB 7, тестовые данные                                              |

Схема и причины решений: [Project_Architecture_Blueprint.md](docs/Project_Architecture_Blueprint.md), [docs/PROJECT.md](docs/PROJECT.md), [docs/adr/](docs/adr/README.md).

## Как вносить изменения

- Работа идёт по историям бэклога: возьмите свободную, отметьте выполненные ACs, смените статус в индексе в том же коммите.
- Коммиты: `feat:` / `fix:` / `chore:` / `docs:` с областью и ID истории, например `fix(server): ... (S0.4)`. Сообщения на английском, документация на русском.
- Секреты, `.env`, дампы и бэкапы не коммитим (`_dumps/`, `_backups/`, `ssl/` в `.gitignore`). Pre-commit хук запускает gitleaks; не обходите его без причины.
