# Аудит доступности

Следуй audit-report: код не правим, отчёт — в `docs/audits/a11y-YYYY-MM-DD.md`.

## Что проверять

1. **Контраст.** Текст ≥ 4.5:1 (крупный ≥ 3:1), элементы интерфейса и фокус ≥ 3:1. Считай по токенам темы; проверь светлую и тёмную темы.
2. **Клавиатура.** Всё доступно без мыши, порядок табуляции совпадает с визуальным, нет ловушек фокуса, диалоги возвращают фокус.
3. **Фокус.** Видимый индикатор на каждом интерактивном элементе, `outline: none` без замены недопустим.
4. **Имена и роли.** Кнопки-иконки с `aria-label`, декоративные `mat-icon` скрыты, у изображений `alt`, нет `div`/`span` вместо кнопок.
5. **Формы.** Поля связаны с подписями, ошибки читаются скринридером (`mat-error`), обязательные поля помечены.
6. **Таблицы и списки.** Заголовки колонок, сортировка объявлена, пустые состояния описаны текстом.
7. **Динамика.** Обновления объявляются через `aria-live`/`LiveAnnouncer`; анимации уважают `prefers-reduced-motion`.
8. **Масштаб.** Работает при увеличении до 200 % и ширине 320 px без горизонтальной прокрутки.

## Как проверять

- Начни с результата линтера (`templateAccessibility` из angular-eslint): `pnpm check --only=client:lint`.
- Живая проверка (браузер, Lighthouse, axe) — только если окружение позволяет; иначе пометь пункт «не проверено».
- Для каждой находки укажи критерий WCAG (1.4.3, 2.4.7, 4.1.2 и т. д.).
